**PC는 정보를 나란히 비교하고, 모바일은 핵심 정보를 먼저 읽도록 구성합니다.** 요약·진행 단계·대표 숫자·기준일·검색을 항상 표시하고, 보조 내용은 화면 폭과 길이에 따라 펼칩니다.

## 현재 지면의 순서와 배치

홈 주소를 열면 IT 브리핑에서 시작합니다. IT 기사가 없는 지난 호는 해당 호의 종합 뉴스를 엽니다. 뒤로 가기와 특정 지면의 바로가기는 선택한 지면을 복원합니다. 종합 뉴스의 읽는 순서는 **1면 → 전국 → 이슈 추적 → 지역 → 언론 → 정치 → 경제 → 산업 → 재정**입니다. 1면 상단의 ‘오늘 정치 한 장’에서 질문·짧은 답·근거를 보여 줍니다. 오른쪽 보조 질문은 좁은 화면에서 아래로 내려오며, ‘기사와 판례 읽기’를 누르면 같은 페이지의 판례 검색과 기사·판결문으로 이동합니다. 분야 메뉴와 전체 메뉴에서도 자료실을 열 수 있습니다. 1면 배치는 [front-page.css](../../../frontend-vanilla-js/src/styles/front-page.css), 뒤쪽 지면은 [reading.css](../../../frontend-vanilla-js/src/styles/reading.css)와 각 컴포넌트가 담당합니다.

첫면과 각 분야의 최대 바깥 너비는 1,320px입니다. 좌우 여백은 화면 폭에 따라 16~52px이며 기기 안전 영역이 더 크면 그 값을 사용합니다. 기사 안쪽 여백은 20~28px입니다. 짧은 기사의 배경을 같은 행의 긴 기사 높이만큼 늘리지 않고 위쪽을 정렬합니다.

이슈 추적·경제 숫자·질문 같은 상세 페이지는 문단을 본문 폭(`--measure`, 42rem)으로 읽습니다. 안내 상자·대표 값 상자·진행 단계·진행 기록·관련 기사 목록도 같은 폭에 맞추고, 상자 안 문단은 상자 폭을 채워 오른쪽에 빈 공간을 남기지 않습니다. 비교 표처럼 열이 많은 자료만 전체 폭을 씁니다. [discovery.css](../../../frontend-vanilla-js/src/styles/discovery.css)

| 영역 | 넓은 화면 | 좁은 화면 |
| --- | --- | --- |
| 이슈 추적 | 상태·현재 단계·요약을 한 건씩 순환하고 전체 기록은 상세에서 읽기 | 한 건씩 좌우로 넘기고 같은 상세 링크로 이동 |
| 오늘 정치 한 장 | 대표 질문과 답 옆에 새벽 삽화를 두고, 바로 아래에서 생활 정책과 시사용어를 선택 | 한 열로 질문·답·출처를 먼저 읽고 다음 질문을 선택 |
| 기사와 판례 | 검색과 대표 쟁점을 같은 행에 배치. 질문·기사 날짜·대법원 사건번호와 양쪽 원문 제공 | 판례 검색을 먼저 보여 주고 질문과 두 원문을 한 열에서 읽기 |

| 언론 | 1,100px 이상에서 제목·설명 왼쪽·검색창 오른쪽 | 설명 아래 전체 폭 검색창 |
| 산업 | 1,100px 이상에서 요약·지표 표 옆에 기준월이 표시된 품목 그래프 배치. 주력산업은 대표 수치로 비교 | 요약·지표 다음에 그래프의 펼침 제목 표시. 주력산업 상세는 목록 아래 표시 |
| IT 브리핑 | 대표 기사와 지면 삽화를 펼침면으로 배치하고 아래에 기사 색인을 세 열로 표시 | 제목·삽화·본문 순서로 읽고 분야 선택과 기사 목록 바로가기를 사용 |

| 날씨 지면 | 전국 뉴스 다음에 해당 호의 예보와 강변 풍경 삽화를 나란히 배치 | 예보와 원문을 읽은 뒤 삽화를 만나는 한 열 |
| 정치 | 1,040px 이상에서 임기·D-Day 왼쪽, 이번 주 일정 오른쪽 | 임기 → D-Day → 일정 순서 |

| 경제 | 1,100px 이상 3개·1,350px 이상 4개를 보는 순환 목록 | 700~1,099px는 2개, 700px 미만은 한 카드 중심 |
| 푸터 | 소개와 지난 호 찾기, 출처 등급, 호별 수집·정정 기록 순서 | 700px 이하에서 한 열로 읽고 긴 수집 기록은 필요할 때 펼침 |

판례 자료실은 분야 색인과 검색 영역으로 구성합니다. 모바일에서는 분야를 선택 상자로 고릅니다. 기사 요약과 제목에 임차권등기·퇴직금·집행정지 등 구체적인 쟁점이 있으면 관련 주제나 검색 결과를 엽니다. 기사 원문과 판례로 이동하는 링크에는 목적지가 각각 드러나는 이름을 붙입니다.

IT 브리핑과 전국 뉴스는 본문 한 편과 제목 목록으로 나눕니다. 기사마다 분야·언론사·보도일과 원문 링크를 표시합니다. IT 지면의 자동 넘김과 이전·다음 버튼은 기사 위에 고정된 순서로 배치합니다. IT 지면은 기사 색인 6건, 전국 뉴스는 목록 5건을 먼저 보여 주고 더보기로 이어 읽습니다. 제목을 선택하면 본문을 바꾸고 새 제목으로 키보드 포커스를 이동합니다.

전국 뉴스 뒤의 날씨 지면은 해당 호에서 확인한 예보 보도에만 연결합니다. 호 날짜와 기사 보도일을 구분해 표시하고, 삽화에는 AI 생성 표시를 붙입니다. 첫 화면의 짧은 밝기 전환과 링크 화살표 움직임은 기기의 동작 줄이기 설정을 따릅니다.

## 핵심 정보와 부가 내용의 펼침

일반 기사 목록은 앞의 3건을 먼저 보여 주고 나머지는 더보기로 엽니다. 아래 부가 내용은 네이티브 `details`·`summary`로 제공하며 PC에서도 독자가 닫을 수 있습니다.

| 부가 내용 | 대상 | 901px 이상 기본 상태 | 900px 이하 기본 상태 |
| --- | --- | --- | --- |
| 머리기사 취재 근거와 확인 기록 | `#leadProvenance` | 접음 | 접음 |
| 오늘의 흐름 | `#natFlow` | 펼침 | 접음 |
| 함께 읽을 주제·핵심 숫자 | `.lead-extras` | 펼침 | 접음 |
| 산업 품목별 그래프 | `#industryChart` | 펼침 | 접음 |
| 이슈 상세의 관련 기사 | `.issue-source-group` | 최신 6건을 표시하고 이전 보도는 6건씩 접음 | 같은 순서로 한 열에 표시 |

[responsiveDisclosure](../../../frontend-vanilla-js/src/core/ui.js)는 같은 페이지에서 넓은 화면·좁은 화면의 사용자 선택을 각각 기억합니다. 폭을 바꿨다가 돌아오면 그 화면에서 고른 상태를 유지하고, 같은 요소에 이벤트를 중복 연결하지 않습니다. 페이지를 새로 열면 기본 상태를 적용합니다.

접힌 항목도 제목과 일정·기사 건수를 표시합니다. 이슈 요약에 현재 단계와 상세 링크를 표시하고, 상세 페이지에서 일정과 기사별 확인 기록을 제공합니다. 경제 지표의 값·변동·원문 기준일과 언론 검색창은 항상 표시합니다. 경제 기준일은 `.econ-base`로 따로 표시합니다. 전체 메뉴에서 접힌 보조 숫자로 바로 이동하면 먼저 해당 영역을 펼칩니다.

## 높이와 스크롤

IT 기사와 이슈 요약은 각 지면에서 가장 긴 항목에 맞춰 높이를 확보합니다. 분야·기사를 바꿔도 본문의 시작점이 움직이지 않으며 큰 글자에서는 지면 높이가 함께 늘어납니다. 기사 본문, 진행 일정, 확인 기록을 끝까지 읽을 때 페이지의 세로 스크롤을 사용합니다.

| 영역 | 높이 기준과 동작 |
| --- | --- |
| 이슈 추적 | 모든 화면에서 한 건만 표시합니다. 자동 넘김과 이전·다음 조작은 페이지 스크롤을 유지하고 상세에서 돌아오면 보던 요약을 복원합니다. |
| 전체 메뉴 | 화면 높이를 쓰고 닫기 버튼 아래의 메뉴를 스크롤합니다. 높이 540px 이하에서는 헤더 여백을 줄입니다. |
| 추적 대화상자 | 이슈 목록에서 상세 페이지로 이동하며 닫기 버튼은 상단에 유지합니다. 높이 540px 이하에서는 창 위아래에 6px씩 여유를 둡니다. |

## 자동 넘김과 경제 지표 순환

[경제 컴포넌트](../../../frontend-vanilla-js/src/components/economy/economy.js)는 로컬 Swiper 14.4.0을 경제 섹션 800px 전에서 비동기로 불러옵니다. 첫 지면 준비를 기다리게 하지 않습니다. 표시 수는 실제 자료 개수 안에서 조정하며, 작은 화면도 폭이 허용되면 다음 카드 일부를 표시합니다. 지표가 두 건 이상이면 화면에 보이는 개수를 조정해 마지막과 처음을 연결합니다. [원본·라이선스·해시](swiper.md)를 함께 보관합니다.

IT 기사, 이슈 요약, 모바일 최근 변경과 경제 지표에 이전·다음, 현재 위치, 자동 넘김 켜기·끄기를 제공합니다. 목록에 포커스가 있을 때 좌우 방향키로도 이동합니다. 자동 넘김 간격은 8초이며 읽는 동작에 맞춰 제어합니다.

| 상황 | 자동 넘김 |
| --- | --- |
| 마우스 호버·목록 안 포커스·영역이 화면 밖·숨긴 탭 | 해당 조건 동안 정지 |
| 직접 이동·모바일 터치·출처 또는 집계 설명 열기 | 사용자가 다시 켜기 전까지 정지 |
| 기기의 동작 줄이기 설정 | 기본 해제, 전환 동작 축소 |

화면 밖 슬라이드의 버튼은 키보드 탐색에서 제외합니다. 목록은 지표명·값·변동·기준일을 같은 순서로 표시합니다. 집계 설명과 출처는 처음에는 접혀 있고, 지표를 선택하면 목록 아래에 한 건만 펼칩니다. 라이브러리 로드·초기화에 실패하거나 늦게 준비되어 읽던 위치를 바꾸게 되는 경우 모든 지표를 격자로 표시하고 상세 읽기는 계속 제공합니다.

주력산업 목록도 같은 흐름으로 읽습니다. 분야별 대표 수치에 실제 지표명을 붙이고, 넓은 화면에서는 다섯 분야를 한 줄에 놓습니다. 좁은 화면에서는 읽기 좋은 너비를 확보하도록 두세 열 또는 한 열로 배치합니다. 상세를 선택하면 분야 요약·전체 지표·출처·관련 기사를 목록 아래에 한 번에 보여 줍니다. 경제와 주력산업의 상세 영역은 문서와 함께 스크롤합니다.

## 탐색과 읽기 도구

[SECTIONS](../../../frontend-vanilla-js/src/core/config.js)를 탐색의 공통 기준으로 사용합니다. 상단 분야 메뉴는 현재 위치를 표시하고, 전체 메뉴는 주제·분야·시도까지 연결합니다. 900px 이하에서는 상단 메뉴를 축약하며 지역 선택은 권역별로 줄바꿈합니다. 하단 탐색은 문서 흐름에 두고 오른쪽 세로 메뉴는 공개 지면에서 숨깁니다.

제호는 주홍색 심벌과 한글 이름을 사용합니다. 1,200px 이상에서는 제호·지면 메뉴·읽기 설정을 같은 줄에 두고, 모든 지면에 같은 높이와 정렬을 적용합니다. 두 번째 줄은 현재 지면과 새 호 구독·공유·지면 목차로 구성하고, 발행일과 수집 상태는 해당 호의 본문 앞에 둡니다. 밝은 화면은 종이색과 먹색, 어두운 화면은 차콜과 아이보리를 바탕으로 쓰며 선택 상태에는 밑줄 또는 상태 문구가 함께 표시됩니다.

PC·모바일 모두 한 화면 이상 내려가면 맨 위로 버튼을 표시합니다. 이동 후에는 제호로 포커스를 돌립니다. 전체 메뉴·추적 모달은 Esc와 닫기 버튼을 제공하고 연 버튼으로 포커스를 되돌립니다. 추적 막대를 숨기면 분야 메뉴에 다시 열기 버튼이 나타납니다. 지난 호와 주제별 기록 링크는 전국 기사 목록 다음에 표시합니다.

‘글자 크게’와 ‘어두운 화면’은 각각 스위치로 제어합니다. 손잡이 위치와 `켬`·`끔` 글자, `aria-checked`로 상태를 전달합니다. 제호·전체 메뉴·지난 호 목록과 이슈·지표 페이지의 선택은 같은 기기에서 이어집니다. 기기 설정과 관계없이 처음에는 밝은 화면으로 열립니다. 어두운 화면을 선택하면 저장하고, 스위치를 끄면 밝은 화면으로 돌아갑니다.

## 문구와 숫자의 표현

결론을 첫 문장에 쓰고 수치·근거·배경을 이어 설명합니다. [readingText](../../../frontend-vanilla-js/src/core/ui.js)는 긴 요약의 첫 문장과 나머지를 시각적으로 나누면서 문자열의 순서·내용을 보존합니다. 가독성을 이유로 제목·본문의 한정어나 수사 상태를 지우지 않습니다. 작성 원칙은 [발행 런북](../planning/editorial.md#글을-읽을-이유를-첫-문장에-두기)을 따릅니다.

상승·하락은 기호와 글자로 전달하고 오류색 `danger`를 하락에 사용하지 않습니다. 출처는 A~E 문자로, 결산·전망은 배지와 선 형태로 구분합니다. 미확인 값을 추정해 채우지 않고, '약'은 원자료가 제공한 정밀도에 맞춰 사용합니다.

추적의 단계는 보도에 따른 편집상 정리이며 공식 해결률이 아닙니다. 최종 발표일이 미확정인 사안은 기간 백분율을 표시하지 않습니다. 경과 기간과 확인된 단계, 예정과 완료를 구분합니다. 산업의 핵심 지표와 품목 그래프도 각각의 기준월을 유지합니다. 자동 발행 표시는 사람의 원문 대조 표시와 구분합니다.

## 시각 기준과 토큰

신문 이름과 머리기사는 명조체로 강조하고, 괘선으로 다음 기사나 섹션의 시작을 구분합니다.

제호·머리기사는 기기에 설치된 명조체, 본문은 한글 고딕체를 사용합니다. macOS·iOS는 AppleMyungjo와 Apple SD Gothic Neo, Windows는 바탕과 맑은 고딕, 그 밖의 기기는 설치된 Noto 또는 시스템 글꼴을 사용합니다. 한글 글꼴이 없는 기기는 같은 출처의 WOFF2를 사용합니다. 현대 한글 11,172자를 한 파일에 담고, 옛한글 자모와 지면에 쓰인 한자는 별도 파일에 담아 필요한 글자만 내려받습니다. 본문 400, 강조 500·700, 제목·대표 숫자 900 굵기와 숫자의 `tabular-nums`를 사용합니다. 기준 글자는 18px, 900px 이상 19px, 큰 글자는 23px입니다. 설명 문단의 공통 최대 너비는 `42rem`입니다. 보조 표기의 토큰 최솟값은 `caption` 0.8rem이며 최신 숫자 띠·지역 선택·토글 상태에는 더 작은 예외가 있습니다.

[한글 완성형 글꼴 원본](https://github.com/google/fonts/tree/1c96438dec81b2b5078557d91315e31fb29b9462/ofl/nanumgothic) · [자모·한자 글꼴 원본](https://github.com/google/fonts/tree/b38c5c93af322c45f633e17ac440ec1e6c94d489/ofl/notosanskr) · [배포 글꼴과 SIL OFL 1.1 라이선스](../../../frontend-vanilla-js/assets/fonts/)

신문·판례·입법 캘린더는 밝은 테마에서 미색 배경 `#f8f6ef`와 잉크 `#242420`, 어두운 테마에서 배경 `#1c1d1b`과 상위 면 `#262724`를 사용합니다. 기사 면·도구·모달은 `surface-raised`로 구분합니다. 기본 화면 모드는 라이트이며 다크를 켰을 때만 `jogan-theme`에 저장합니다. 제호·전체 메뉴·목록 페이지와 관리자 화면이 저장한 색상 선택을 적용하고, 저장소가 막혀도 현재 페이지 전환은 동작합니다. 작은 초기 코드가 CSS 전에 모드만 적용하고 비동기 `core/theme.js`가 조작·저장을 연결합니다.

공개 신문과 법률면의 지면색·제호 서체는 [press.css](../../../frontend-vanilla-js/src/styles/press.css)에서 정의합니다. 공통 컨트롤·그래프의 기본 색·글자·간격 원본은 [tokens.json](../../../frontend-vanilla-js/src/styles/tokens.json)입니다. 생성 CSS를 직접 편집하지 않고 아래 명령으로 갱신합니다.

```bash
python3 backend-python/pipeline/build/build_tokens.py
python3 backend-python/pipeline/build/build_tokens.py --check
```

밝은 신문·법률면의 주요 행동은 적갈색 `#84362f`, 키보드 포커스는 청색 `#07588a`로 표시합니다. 산업 강조는 `#a14a00`입니다. 어두운 테마 값은 토큰 원본에 따로 정의하며 화면 모드 스위치로 적용합니다.

## 공통 컴포넌트와 상태

| 역할 | 클래스·함수 | 유지할 동작 |

| 조작·탐색 | `kj-btn`, `kj-chip`, `kj-cats`, `kj-tabbar`, `kj-drawer` | 같은 섹션 정보와 상태·포커스 |

첫 접속은 텍스트와 표시자로 읽기 준비를 알립니다. 데이터 요청은 최대 12초 뒤 중단하며, 스크립트가 실행되지 않으면 20초 후 재시도와 미리 만든 호 요약을 제공합니다. 정정·최신 숫자 요청은 본문 준비를 지연시키지 않습니다. 860px 이하의 긴 수치·비교 표·주제 선택은 아래로 흐르게 하며 페이지 전체를 숨겨 가로 넘침을 덮지 않습니다.

접근성 확인 목표는 본문 대비 4.5:1·주요 비문자 요소 3:1·조작 영역 44px 이상입니다. 색 외에 문자·기호·형태를 쓰고 키보드 포커스와 `aria-current`·버튼의 `aria-expanded`·기본 `details` 동작을 유지합니다. 동작 줄이기 설정에서는 스크롤·서랍·로딩 애니메이션을 줄이거나 끕니다. 확인할 때는 밝은 화면과 어두운 화면, 큰 글자, 오류 상태에서 글자가 읽히고 키보드로 조작되는지 점검합니다. [공개 지면 브라우저 검사](../../tests/browser/smoke.cjs)

관리자도 같은 토큰과 버튼·배지를 사용합니다. 연결 전에는 비공개 통계를 숨기고 공개 발행 현황과 설정 안내만 표시합니다. 0건과 조회 실패를 구분하고, 인증 만료·권한 오류·연결 해제 시 수치를 제거합니다. 760px 이하에서 그래프·목록을 아래로 흘리고 긴 표 제목을 줄바꿈합니다. 실제 계정 연결 조건과 검증 범위는 [관리자 문서](../dev/ga4-admin.md)를 따릅니다.

## 관리자의 입력과 독자의 복사 동작

## 이메일 구독 폼과 메일 본문

구독 폼은 아이디 칸과 메일 서비스 선택(국내 주요 10곳 + 직접 입력)으로 주소를 받고, 제출할 때 원래 `email` 칸 하나로 합쳐 보냅니다. 자바스크립트를 끄면 한 칸짜리 주소 입력이 그대로 보입니다. [구독 영역 생성](../../../backend-python/pipeline/build/reader_panel.py) · [폼 동작](../../../frontend-vanilla-js/src/core/reader.js)

**메일 본문은 표와 인라인 여백으로만 배치합니다.** 네이버 메일·Gmail 앱은 `flex`·`grid`·`<style>`·CSS 변수를 지우거나 무시하고, `<p>` 기본 여백과 `a`의 `padding`·`inline-block`도 앱마다 다르게 그립니다. 그래서 블록마다 `<tr><td>` 한 줄을 쓰고 간격은 `td`의 `padding`으로 잡습니다. 버튼은 배경색을 `td`의 `bgcolor`로 칠하고 `a`에는 글자만 둡니다. 화면 가장자리와 본문 사이에는 8px 여백을 두고, 본문 폭은 최대 600px, 한글은 `word-break:keep-all`로 어절 단위로 줄바꿈합니다. 색은 사이트 토큰 값을 그대로 적습니다. [메일 본문 생성](../../../backend-python/pipeline/publish/notify_email.py)
