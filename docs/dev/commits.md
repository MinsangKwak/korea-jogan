# 커밋 메시지 작성 기준

**커밋 제목에는 바뀐 내용을, 본문에는 변경 이유와 검증 범위를 남깁니다.** 한 커밋에는 설명 가능한 주제 하나를 담고, 문서마다 목적이 다르면 커밋도 나눕니다.

[문서 안내](../README.md) · [브랜치와 배포](branches.md) · [검사기](../../dev/tools/check_commit_msg.mjs)

## 형식

```text
종류(범위): 변경한 내용

변경이 필요했던 이유와 선택한 방법
```

종류는 소문자, 제목은 한국어로 작성합니다. 범위와 본문은 필요할 때만 씁니다. PR 제목도 같은 형식을 사용합니다.

| 검사 항목 | 기준 |
| --- | --- |
| 제목 길이 | 종류·범위를 포함한 한 줄 전체 72자 이내 |
| 제목 끝 | 마침표를 붙이지 않음 |
| 종류·범위 | 아래 목록에서 선택. 범위는 생략 가능 |
| 예외 | Git이 생성한 `Merge`·`Revert` 제목 |

## 범위 선택

| 범위 | 대상 |
| --- | --- |
| `site` | 화면·탐색·표시 동작 |
| `issue` | 날짜별 호와 정정 데이터 |
| `scripts` | 수집·검사·생성 스크립트 |
| `docs` | README·기획·설계·운영 문서 |
| `infra` | 워크플로·배포·저장소 설정 |

## 종류 선택

| 종류 | 용도 | 예시 |
| --- | --- | --- |
| `feat` | 새 기능 | `feat(site): 홈에서 기준이 다른 숫자 비교 제공` |
| `fix` | 동작·데이터 오류 수정 | `fix(issue): YYYY-MM-DD호 환율 기준일 정정` |
| `style` | 화면 표현·문구 조정 | `style(site): 숫자 카드의 기준일 문구 정리` |
| `refactor` | 동작을 유지한 구조 변경 | `refactor(site): 지역 선택 로직을 컴포넌트로 분리` |
| `docs` | 문서 변경 | `docs(docs): README를 최신 구현과 읽는 순서로 정리` |
| `test` | 검사 코드 변경 | `test(scripts): 초안 배포 차단 사례 추가` |
| `data` | 발행 자료 갱신 | `data(issue): YYYY-MM-DD호 초안` |
| `ci` | 자동 검사·배포 설정 | `ci(infra): 배포 전에 토큰 생성 결과 검사` |
| `release` | 여러 변경을 묶은 버전 갱신 | `release: 발행 자동화 개선 반영` |
| `sync` | 브랜치 동기화 | `sync: 검증한 코드의 main·deploy 반영` |
| `chore` | 그 밖의 유지보수 | 구체적인 다른 종류를 먼저 검토 |

## 문서별 커밋과 병합

문서별 커밋을 요청받았다면 README·기술 설계·운영 절차를 각각 설명하는 제목으로 나눕니다. 여러 문서를 같은 제목으로 반복하거나, 문서 작업을 모두 ‘가독성 개선’으로만 기록하지 않습니다.

병합 시 커밋을 보존할지 squash할지는 해당 요청에 따릅니다. 작업 중 파일별 커밋을 나누는 것과 최종 PR을 한 커밋으로 합치는 것은 별개의 선택입니다. 이미 공개된 과거 이력은 이 규칙에 맞추기 위해 다시 작성하지 않습니다.

본문에는 선택의 이유와 검증 범위를 씁니다. 예를 들어 ‘발행 시각을 06시로 통일하고 사람 확인과 자동 공개를 구분했다’처럼 판단을 확인할 수 있게 설명합니다. 기능 추가를 사용자 증가·검색 순위·정확도 향상 등의 성과로 바꿔 쓰지 않습니다. 테스트 결과는 실제 실행한 범위만 적고, 공동 작성자 꼬리표는 사실에 맞게 유지합니다.

## 검사 실행

저장소 루트에서 로컬 훅을 설정합니다.

```bash
git config core.hooksPath dev/tools/githooks
```

메시지 파일 하나 또는 PR의 커밋 범위를 검사할 수도 있습니다.

```bash
node dev/tools/check_commit_msg.mjs .git/COMMIT_EDITMSG
node dev/tools/check_commit_msg.mjs --range origin/main..HEAD
```

검사기는 형식·종류·범위·길이·끝 마침표를 확인합니다. 한국어 여부나 본문 품질까지 판정하지는 않습니다. PR 검사 실패가 실제 병합을 막는지는 저장소 보호 설정에 달려 있습니다.

이 기록 기준은 2026-10-19부터 적용합니다.
