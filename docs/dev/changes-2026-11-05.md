## 문서 반영 뒤 통합 검사에서 확인한 CSP 대기 오류

문서 PR #100의 병합 후 검사와, 기능 브랜치 운영 지침 PR #101의 `dev` 통합 검사에서 `object-src 미차단`이 간헐적으로 발생했습니다. PR의 같은 화면 코드 검사는 성공했지만 통합 검사는 실패해 승격을 중단하고 조사했습니다.

`security.cjs`는 CSP 이벤트가 5개 이상이면 결과를 읽었습니다. 인라인 코드와 외부 스크립트가 같은 `script-src-elem` 이벤트를 각각 만들기 때문에 이벤트 수가 5개여도 필요한 지시어가 모두 도착한 것은 아닙니다. `object-src` 이벤트가 늦으면 정상 차단 상태에서도 검사가 먼저 끝났습니다.

검사 완료 조건을 이벤트 개수에서 **필요한 지시어 전체의 관측**으로 바꾸고 같은 목록으로 최종 차단 결과를 검증합니다. 공개 CSP와 화면 코드는 변경하지 않습니다.

| 확인 조건 | 기존 검사 | 수정 검사 |
| --- | --- | --- |
| `object-src` 이벤트를 200ms 지연 | `object-src 미차단`으로 실패 재현 | 홈·지난 호·관리자 3경로 통과 |
| `object-src` 이벤트 누락 | 비교 대상 아님 | 시간 초과로 실패해 누락을 통과시키지 않음 |
| 일반 이벤트 흐름 | 기존 CI 성공·간헐 실패 기록 | 홈·지난 호·관리자 3경로 통과 |

지연·누락을 주입한 확인은 임시 검사본에서 수행하고 운영 파일·정책에 적용하지 않았습니다. 이 수정은 기능 브랜치·별도 PR로 분리해 `dev`의 통합 CI를 다시 확인합니다.

## 남은 확인과 문서 범위

- GitHub 예약이 지정 시각보다 늦게 시작한 원인과 다음 날 정상 시각 발행 여부.
- 가비아 CNAME은 등록됐고 Vercel HTTPS 확인 이력도 있으나, 사용자 네트워크에서의 개발 도메인 접속 완료는 별도 확인.
- `dev`는 지면·브랜드 개편의 `33efeb0`, 운영 발행본은 `d5b493a` 기준이다. 다음 코드 승격 전 안정 이력을 개발 브랜치에 포함해야 한다.

최초 최신화 PR #100은 MD만 변경했고, 후속 PR #101은 기능 브랜치·커밋·태그 지침을 등록했습니다. 조사·공개 확인 예약 2개의 지시문에도 규칙을 반영하되 시각과 허용 범위는 유지했습니다. 이후 위 CSP 검사 대기 오류를 별도 수정했으며 기사 본문과 공개 화면·보안 정책은 바꾸지 않았습니다. 문서 작업 시작 시점 `main`·`deploy`는 `d5b493a`였으며 후속 커밋과 실제 배포 소스 SHA는 구분합니다. 과거 캡처·검증 수치는 당시 기록으로 보존합니다.
