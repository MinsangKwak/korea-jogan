# 2026-10-23 운영 확인과 모바일 안정화

## 운영 상태

확인 대상은 `https://korea-jogan.com/`과 `158314f`의 공개 데이터입니다. 방문자 수와 동작·발행 수치를 구분합니다.

| 항목 | 확인 결과 |
| --- | --- |
| 공개 호 | 5개, 최신 2026-10-23 |
| 최신 호 상태 | 자동 발행, 사람 확인 전 |
| 10월 23일 실제 발행 기록 | 한국 시간 08:47, `review.auto: true` |
| 예약 시각 | 06:00, 이날 실제 발행 기록은 목표보다 2시간 47분 늦음 |
| 최신 호 콘텐츠 | 전국 24건, 시도 48건, 언론 주제 3개·기사 30건 |
| 사이트 응답 | 첫 화면·발행 목록·최신 호 JSON 모두 HTTP 200 |
| 최근 작업 | 확인한 최근 Actions 실행 8건 모두 성공 |
| 방문·행동 측정 | GA4 ID 연결, GoatCounter 주소는 비어 있음 |
| 방문자·페이지뷰 실측 | 현재 연결된 도구로 GA4 보고서를 조회할 수 없어 미확인 |

발행 시각은 JSON의 기록과 Actions 실행 시각으로 확인했습니다. GitHub 예약 작업은 정확한 시각 실행을 보장하지 않으며, 이번 수정은 예약 시스템을 변경하지 않습니다.

작업 환경에서 다시 측정한 공개 응답은 첫 화면 5,127ms, 발행 목록 5,133ms, 최신 호 JSON 5,054ms의 첫 응답 시간(TTFB)을 보였습니다. 최초 단일 확인은 첫 화면 4,170ms였습니다. 네트워크·중계 경로가 포함된 단일 환경 측정으로, 한국 모바일 실사용자의 평균 속도나 서버 자체 처리 시간은 아닙니다. 이 수치로 개선율을 산출하지 않습니다.

## 수정한 내용

- 발행 검사에서 빈 주제, 잘못된 중첩 객체·배열·숫자, 중복 주제 ID, 비교 표의 열 수 불일치를 차단합니다. 깨진 JSON과 발행 목록도 예외 종료 대신 검사 실패로 보고합니다.
- 화면 초기화 전체를 오류 경계로 감쌌습니다. 렌더링이 끝나기 전에는 정적 요약을 지우지 않으며, 실패 시 요약·오류 안내·재시도를 제공합니다.
- 배포 HTML에 해당 호 JSON과 발행 목록을 포함해 정상 첫 진입에서 본문 표시 전 별도 JSON 요청 2건을 제거했습니다. 개발 화면과 날짜 쿼리는 필요하면 파일을 요청합니다. 삽입한 JSON의 `<`는 이스케이프합니다.
- 외부 글꼴 CSS가 본문을 차단하지 않게 했습니다. 정정 기록·최신 숫자는 본문 표시 이후 처리합니다.
- 로딩 상태를 텍스트와 표시자로 안내하고 데이터 요청에 12초 제한을 둡니다. 화면 스크립트 누락 시에도 20초 후 재시도와 정적 요약을 제공합니다. 움직임 줄이기 설정을 존중합니다.
- 모바일 시도·주제 선택, 최신 숫자, 긴 값·비교 표를 화면 폭 안에서 세로로 배치합니다. 페이지 전체의 가로 넘침을 숨겨 내용을 자르지 않습니다.
- 비교 카드의 `pick`이 인덱스 두 개가 아닌 편집 메모이면 첫 값·마지막 값으로 표시합니다. 기존 미상 기사 날짜는 ‘발표일 미확인’으로 보입니다.
- 메뉴를 연 직후 닫으면 예약된 열림 프레임도 취소해 서랍이 다시 열리는 경쟁 상태를 막습니다.
- GA4에 `app_ready`·`app_load_error`와 초기화 시간 `duration_ms`를 추가합니다. 실제 집계 여부는 GA4 보고서에서 별도로 확인해야 합니다.

## 검증

- 공개 데이터 5개 호의 배포 검사와 디자인 토큰 일치 검사 통과.
- Python 테스트 42개 통과.
- Playwright 실제 Chromium 검사 22개 시나리오 통과: 320·360·390·430·768·900·1440px, 일반·큰 글자, 공개 호 5개, 날짜 쿼리, 느린 요청, 404, 빈 주제, 렌더링 중 오류, 스크립트 누락, 요청 시간 초과, 메뉴·Esc·포커스, 지역 선택, 비교 표·검색, 보조 데이터 오류.
- 배포 페이지가 본문 JSON을 다시 요청하지 않는 것을 브라우저에서 확인.
- JavaScript 구문 검사와 `git diff --check` 통과.
- 외부 정적 UI 검사도 실행했습니다. 남은 9건은 HTML의 버튼에 인라인 이벤트가 없다는 항목으로, 별도 JS의 이벤트 연결을 인식하지 못한 결과입니다. 이 검사는 통과로 보고하지 않으며, 메뉴·크기·검색 등 실제 동작은 브라우저 검사로 확인했습니다.

브라우저 검사는 로컬 파일을 HTTP 응답으로 제공하고 오류를 주입해 실제 Chromium에서 실행합니다. CI에도 같은 검사를 추가했습니다. iOS Safari 실기기와 실제 느린 이동통신 환경의 체감 속도는 별도 확인이 필요합니다.

```bash
python3 dev/pipeline/publish/validate.py --deploy
python3 dev/pipeline/build/build_tokens.py --check
python3 -m unittest discover -s dev/tests
cd dev/tests/browser
npm ci
npx playwright install chromium
npm test
```
