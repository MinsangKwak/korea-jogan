# AI 작업 지침

**작업 범위를 지키고, 구현 사실과 사람의 확인 여부를 구분해 한국어로 기록합니다.** 서비스 개요는 [README](../../README.md), 현재 문서의 읽는 순서는 [문서 안내](../README.md), 구현 구조는 [기술 설계](architecture.md)에서 확인합니다.

## 작업을 시작할 때

1. 현재 소스·관련 문서·원격 이력을 확인합니다.
2. 요청한 범위에서 작업합니다. 문서 변경 요청이면 별도 요청 없이 화면·데이터·워크플로를 바꾸지 않습니다.
3. `dev`에서 작업을 시작합니다. `main`·`deploy`에는 직접 수정 커밋을 만들지 않습니다.
4. 변경 내용과 검증 결과를 기록하고 [브랜치 절차](branches.md)에 따라 반영합니다.

## 언어와 근거

사용자 답변·진행 안내·문서·커밋·PR·이슈·리뷰는 한국어로 작성합니다. 코드 식별자, 명령어, 경로, 오류 원문, 정해진 커밋 종류는 원래 표기를 유지합니다. 커밋 제목은 [작성 규칙](commits.md)을 따릅니다.

현재 구현과 계획을 나눠 씁니다. 코드·이력으로 확인하지 못한 구현, 사용자 반응, 개선 수치를 사실처럼 적지 않습니다. AI의 형식 검사나 자동 테스트를 사람이 원문을 대조한 결과로 표현하지 않습니다.

## 유지해야 할 발행 정책

**사용자가 중단을 지시하기 전까지 매일 자동 발행 흐름을 유지합니다.** 00시 Codex 예약 작업은 조사·초안·문장 편집·검사 후 `dev`에 저장하고, 06시 아침 발행은 조건을 충족한 오늘 호를 `main`·`deploy`로 올립니다. 실제 예약·재시도 시각은 [브랜치 문서](branches.md#일일-발행)를 따릅니다.

기존 Claude 00시 조사와 06:05 보조 예약은 2026.11.04에 꺼졌고 Codex로 이관합니다. Codex 예약 2개는 등록·활성 상태를 확인했으며 첫 예약은 한국 시간 2026-11-05, 첫 실행 결과는 미확인입니다. [자동화 이관 문서](publish-automation.md#현재-상태)에서 등록과 실제 실행을 구분합니다. 별도 01시 편집 예약은 두지 않습니다. 00시에는 [조사·편집 운영](../planning/editorial.md)에 따라 사실 초안을 임시 보존한 뒤 허용 문자열을 편집하고 `check_editorial.py --baseline-file`·`validate.py`로 검사합니다. 시작 원격 SHA가 같을 때만 오늘 초안+색인과 실제 추적 갱신을 역할별 커밋으로 직접 `dev`에 반영합니다. 공개 호·수치·출처·열람/확인 기록을 문체 편집으로 바꾸지 않습니다. 06:05는 현재 공개 날짜·워크플로 기록의 읽기 전용 확인과 실패 진단만 수행합니다. 원래 요청한 `publish.yml` 직접 실행은 연결 도구의 기능 부재와 대체 재실행의 자동 승인 검토 거절로 별도 승인·실행 경로 확인 대기입니다. 코드·데이터 수정, 빈 push 우회나 강제 push는 하지 않습니다. 기존 GitHub 예약·재시도는 유지합니다.

| 확인 방식 | 실행 | 남길 기록 |
| --- | --- | --- |
| 사람이 원문과 대조 | `approve.py --by 이름` | 실제 확인자·시각·확인 범위, 편집자 확인 표시 |
| 확인되지 않은 초안을 자동 공개 | 워크플로의 `approve.py --auto` | `review.auto: true`, 자동 발행 표시 |

사람이 확인하지 않은 호에 확인자 이름을 임의로 적지 않습니다. 자동 공개도 데이터 검사와 배포 규칙을 통과해야 합니다. 조사·공개·정정 방법은 [발행 런북](../planning/runbook.md)에 있습니다.

## 발행이 실패했을 때

06시 이후 오늘 호가 보이지 않으면 초안 존재 → 최신 호 색인 → 검사 결과 → 브랜치 빨리 감기 순서로 원인을 확인합니다. 수정 후 Actions의 아침 발행을 수동 실행합니다. 강제 push나 확인 기록 조작으로 다른 변경을 덮어쓰지 않습니다.
