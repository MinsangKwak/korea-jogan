# AI 작업 지침

**개발 코드와 일일 데이터를 분리하고, 구현 사실과 사람의 확인 여부를 구분해 한국어로 기록합니다.** [README](../../README.md) · [문서 안내](../README.md) · [환경 기준](environments.md) · [브랜치 절차](branches.md)

## 작업을 시작할 때

1. 현재 소스·문서·원격 이력과 요청 범위를 확인합니다.
2. 기능·화면 변경은 기능 하나의 `feature/<기능명>` 브랜치에서 구현·검증하고 폴더·역할별 커밋을 나눕니다. PR은 기능 하나로 묶으며 배포 준비가 끝난 PR만 `dev`에 병합합니다. 일일 조사는 안정 `main`에서 `daily/YYYY-MM-DD`를 만듭니다.
3. `main`·`deploy`에 직접 수정 커밋을 만들지 않습니다. 코드 승격은 정확한 SHA와 CI·보호된 개발 배포를 확인하고, 일일 발행은 허용 데이터만 안정 코드에 반영합니다.
4. 문서 요청에 화면·데이터를 섞지 않습니다. 커밋은 사용자 요청에 맞춰 문서·폴더·역할별로 나누고 검증 결과를 기록합니다.

## 언어와 근거

사용자 답변·문서·커밋·PR·이슈·리뷰는 한국어로 씁니다. 식별자·명령·오류 원문은 원래 표기를 유지하고 [커밋 기준](commits.md)을 따릅니다.

현재 구현·원격 반영·실제 배포·계획을 구분합니다. 설정 등록을 배포 성공으로, 자동 검사를 사람의 원문 대조로, 기능 검사를 실제 독자 성과로 표현하지 않습니다. 이전 날짜의 기록과 검증 수치는 당시 근거로 보존합니다.

## 개발 미리보기와 운영

`dev`는 배포 준비가 된 기능의 통합 검증과 Vercel의 보호된 미리보기 대상입니다. 미완성·배포 보류 기능은 피처 브랜치에 둡니다. `main`은 승인·검증한 안정 코드, `deploy`는 운영 Pages 기준입니다. 개발 도메인·인증·DNS는 [환경 상태](environments.md)에서 확인합니다. 개발 미리보기는 GA4 비활성·검색 제외·관리자 읽기 전용이며 공개 전 초안 데이터를 포함하지 않습니다.

운영 공개는 [브랜치 절차](branches.md)를 따릅니다. 정확한 `dev` SHA의 CI·해당 Vercel 배포·운영자의 인증/관리자 확인·조상 관계를 확인하지 않은 코드를 승격하지 않습니다. 토큰 없는 CI가 현재 Vercel 인증 정책까지 증명한다고 적지 않습니다. 배포 완료는 해당 SHA의 Pages 성공과 공개 `build-info.json`의 실제 소스 SHA·호 날짜를 확인한 뒤 기록합니다. 일일 발행으로 `dev` 전체를 병합하지 않습니다.

기능별 검사 뒤에도 통합 `dev`의 빌드·테스트를 다시 통과해야 합니다. 최신 안정 이력을 포함한 SHA를 고정하고 검증 뒤 변경이 생기면 다시 검사합니다. 기능 릴리스에는 고정 SHA의 고유한 태그를 남기고 기존 태그를 이동하지 않습니다. 현재 승격 워크플로에는 태그 자동 생성 단계가 없으므로 실제 생성 전에는 완료로 보고하지 않습니다. 일일 기사 데이터와 문서만의 반영은 기능 릴리스와 구분합니다.

## 유지해야 할 일일 발행 정책

**사용자가 중단하기 전까지 매일 조사·발행 흐름을 유지합니다.** 00시에는 `main` 기반 `daily/YYYY-MM-DD`에 오늘 JSON·색인·실제 새 추적 근거만 준비합니다. 사실 초안을 임시 보존하고 허용 문자열을 편집한 뒤 `check_editorial.py --baseline-file`·`validate.py`를 통과시킵니다. 일일 브랜치 생성·갱신은 예상 SHA를 확인하고 역할별 커밋으로 반영합니다. 코드·문서·과거 호를 함께 바꾸지 않습니다. [조사·편집 기준](../planning/editorial.md)

기존 Claude 00시·06:05 예약은 2026.11.04에 꺼졌고 Codex로 이관했습니다. 11/05 첫 조사·일일 초안 저장과 읽기 전용 공개 확인이 실행됐습니다. 오늘 호는 관리자 보안 검사 수정 뒤 운영자 요청으로 복구했으며, 뒤늦은 GitHub 예약은 이미 공개된 호의 상태 확인에 성공했습니다. 정시 최초 발행 성공과 구분합니다. [자동화 상태](publish-automation.md#현재-상태)와 [복구 근거](changes-2026-11-05.md)를 따릅니다.

06:05 Codex는 공개 날짜·워크플로 기록을 읽기 전용으로 확인하고 실패 원인을 보고합니다. 직접 워크플로 실행은 도구 기능 부재와 대체 재실행의 자동 승인 검토 거절로 확인 대기입니다. 코드·데이터 수정·빈 push·강제 push로 우회하지 않습니다. 실제 공개는 기존 GitHub 06:07·06:37·07:17·08:17 예약이 맡습니다.

안정 `main`의 아침 발행 코드만 실행합니다. 고정한 일일 SHA의 CI 성공과 허용 파일을 확인한 뒤 오늘 자료만 가져오며 소스 일일 브랜치의 코드는 실행하지 않습니다.

| 확인 방식 | 실행·기록 |
| --- | --- |
| 사람이 원문과 대조 | 실제 확인 이후 `approve.py --by 이름`, 확인자·시각·범위 기록 |
| 미확인 초안 자동 공개 | 아침 워크플로의 `approve.py --auto`, `review.auto: true`와 자동 발행 표시 |

사람이 확인하지 않은 호에 확인자 이름을 만들지 않습니다. 문체 편집으로 수치·출처·열람·확인 기록을 바꾸지 않습니다. 조사·공개·정정의 구체적 절차는 [런북](../planning/runbook.md)을 따릅니다.

## 발행이 실패했을 때

오늘 `daily` 존재 → 오늘 JSON·색인 → 고정 SHA의 CI → 데이터 선별 검사·동시 변경 → 안정본·Pages 순서로 읽기 전용 진단을 합니다. 감독 예약은 진단만 보고합니다. 운영자가 수정·재실행할 때도 강제 push나 전체 개발 브랜치 병합으로 우회하지 않습니다.
