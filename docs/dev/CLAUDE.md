# AI 작업 지침

**한국어로 작업 내용을 기록하고, 자동 발행과 사람의 확인을 구분합니다.** 이 문서는 AI가 저장소를 수정할 때 지켜야 할 운영 기준입니다. 서비스 기획·구현 설명은 [README](../../README.md)와 [기술 설계](architecture.md)를 참조합니다.

## 언어와 기록

사용자 답변·진행 안내·문서·커밋·PR·이슈·리뷰는 한국어로 작성합니다. 코드 식별자, 명령어, 경로, 오류 원문, 정해진 커밋 종류 등은 원래 표기를 유지합니다. 커밋 제목은 [작성 규칙](commits.md)을 따릅니다.

변경한 기능과 계획 중인 기능을 구분합니다. 코드와 이력으로 확인하지 못한 구현, 사용자 반응, 개선 수치를 사실처럼 적지 않습니다. AI의 형식 검사를 사람의 원문 확인으로 표현하지 않습니다.

## 변경 범위와 브랜치

작업 전 현재 소스와 관련 문서를 읽습니다. 문서 변경 요청이라면 별도 요청 없이 화면·데이터·워크플로를 바꾸지 않습니다. 작업은 `dev`에서 시작하며 `main`·`deploy`에 직접 수정 커밋을 만들지 않습니다. 구체적인 반영 경로는 [브랜치 규칙](branches.md)에 있습니다.

## 발행 정책

사용자가 중단을 지시하기 전까지 매일 자동 발행 흐름을 유지합니다. 00시 예약 작업은 초안을 `dev`에 저장하고, 06시 `publish.yml`은 조건을 충족한 오늘 호를 `main`·`deploy`로 올립니다.

| 구분 | 실행 | 남길 기록 |
| --- | --- | --- |
| 사람이 원문과 대조한 호 | `approve.py --by 이름` | 실제 확인자·시각·확인 범위, 화면의 편집자 확인 표시 |
| 06시까지 확인되지 않은 초안 | 워크플로의 `approve.py --auto` | `review.auto: true`, 화면의 자동 발행 표시 |

사람이 확인하지 않은 호에 확인자 이름을 임의로 적지 않습니다. 자동 공개 역시 데이터 검사와 배포 규칙을 통과해야 합니다. 상세한 조사·공개·정정 절차는 [발행 런북](../planning/runbook.md)을 따릅니다.

## 발행 실패 대응

06시 이후 오늘 호가 보이지 않으면 초안 존재, 최신 호 색인, 검사 결과, 브랜치 빨리 감기 순서로 원인을 확인합니다. 수정 후 Actions의 아침 발행을 수동 실행합니다. 다른 변경을 덮어쓰기 위한 강제 push나 확인 기록 조작으로 우회하지 않습니다.
