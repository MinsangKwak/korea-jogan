# GA4 운영 화면 연결과 확인

**[운영 화면](https://korea-jogan.com/admin/)에서 GA4 기간별 통계와 공개 발행 현황을 확인합니다.** 통계는 Google 계정의 조회 권한을 검사한 뒤 표시합니다. 발행 현황은 로그인 없이 볼 수 있는 공개 JSON입니다.

[문서 안내](../README.md) · [기술 설계](architecture.md) · [화면 코드](../../dev/web/admin/) · [측정 코드](../../dev/web/src/core/metrics.js)

## 현재 구현과 연결 상태

| 항목 | 저장소에서 확인되는 내용 |
| --- | --- |
| 조회 대상 | GA4 속성 `559927668`, 호스트 `korea-jogan.com` |
| 배포 | 기존 GitHub Pages의 `/admin/`. 별도 서버·서비스 계정 키 없음 |
| 인증 | Google Identity Services의 읽기 전용 단기 OAuth 토큰 |
| 기본 설정 | [config.js](../../dev/web/admin/config.js)에 공개 클라이언트 ID 설정 |
| 보관 | 토큰·통계는 현재 창의 메모리에만 유지. 새로고침하면 재연결 |
| 자동 검사 | OAuth·GA4 응답을 대체한 관리자 브라우저 검사 24건(2026.11.06 기준) |

자동 검사는 실제 계정의 인증이나 운영 측정값을 검증한 결과가 아닙니다. Google Cloud의 현재 동의 화면·테스트 사용자·허용 원본 설정은 콘솔에서 확인해야 합니다.

## 기존 설정으로 연결하기

1. `/admin/`을 열고 **Google 계정으로 연결**을 누릅니다.
2. 속성 `559927668`의 조회 권한이 있는 계정을 선택해 동의합니다.
3. 오늘·최근 7일 통계와 기간별 이용 흐름이 표시되는지 확인합니다. 오늘의 수치는 GA4 처리 지연으로 미완성일 수 있습니다.

인증 도구가 늦게 준비되면 안내 후 연결 버튼을 다시 누릅니다. 새로고침·인증 만료 뒤에는 다시 연결합니다. 사용을 마치면 **연결 해제**로 토큰을 폐기하고 표시한 통계를 지웁니다.

## 새 OAuth 설정이 필요한 경우

**GA4 보고서 조회 권한과 웹 앱의 API 호출 설정은 별개입니다.** 계정 권한만 추가해도 동의 화면·허용 원본·API 설정이 맞지 않으면 연결되지 않습니다.

1. Google Cloud 프로젝트에서 **Google Analytics Data API**를 사용 설정합니다.
2. Google Auth Platform에서 앱 이름·연락처·동의 화면을 설정합니다. 테스트 모드라면 연결할 계정을 테스트 사용자로 등록합니다.
3. **웹 애플리케이션** OAuth 클라이언트를 만들고 승인된 JavaScript 원본에 `https://korea-jogan.com`을 등록합니다. 로컬 인증 검사는 `http://localhost:8000`도 등록합니다. 원본에는 `/admin/` 경로를 붙이지 않습니다.
4. 읽기 범위는 `https://www.googleapis.com/auth/analytics.readonly`만 요청합니다. 연결할 계정에도 대상 GA4 속성의 조회 권한이 있어야 합니다.
5. 화면의 **처음 연결하는 경우 · Google OAuth 설정**에 `…apps.googleusercontent.com` 형태의 공개 클라이언트 ID를 입력합니다. 클라이언트 보안 비밀이나 서비스 계정 JSON은 입력하지 않습니다.
6. Google 계정으로 연결해 계정 선택·동의를 완료합니다.

클라이언트 ID는 공개 식별자입니다. 입력한 ID는 현재 창에 적용하고 가능하면 이 브라우저의 `localStorage`에 저장합니다. **새로고침 시에는 배포된 `CONFIG.clientId`가 우선**이며, 배포 기본값이 비어 있을 때 저장된 ID를 읽습니다. 모든 기기에 새 기본값을 적용하려면 `config.js`를 수정해 배포합니다. 보안 비밀은 브라우저 코드에 넣지 않습니다.

2026-10-25 설정 기록에는 `korea-jogan-admin` 프로젝트의 웹 클라이언트와 테스트 모드·외부 동의 화면, 위 두 원본이 남아 있습니다. 이 과거 기록만으로 현재 콘솔 상태를 확정하지 않습니다. Google Analytics에 로그인한 브라우저의 세션을 추출하거나 재사용하지 않습니다.

## 표시 정보와 갱신

| 영역 | 표시 기준 | 갱신 |
| --- | --- | --- |
| 오늘과 이번 주 | 오늘·최근 7일 방문자, 조회수, 1인 평균 체류 | 화면이 보일 때 5분마다·수동 새로고침 |
| 이용 흐름 요약 | 오늘·최근 7일·최근 28일의 방문자·조회수·세션·1인 평균 체류 | 5분마다·기간 변경 |
| 방문자 추이·접속 기기 | 오늘은 시간별, 그 밖은 날짜별 방문자·조회수 / 기기별 방문자 | 이용 흐름과 함께 |
| 섹션별 체류 | 섹션을 읽은 사람, 1인 평균·총 체류 시간 | 이용 흐름과 함께 |
| 페이지·유입·지역 | 경로별 조회수·체류, 채널별 세션, 시도별 방문자 | 이용 흐름과 함께 |
| 공개 발행 현황 | 최신 호·공개 호 수·확인 방식·확인 기록 시각 | 진입 시·실패 후 재시도 |

보고서의 날짜 범위는 GA4 속성 시간대를 따르고, 화면의 조회 시각은 KST로 표시합니다. 보고서는 `hostName = korea-jogan.com`으로 제한합니다. 방문자는 차원 없는 집계를 사용하며 페이지별·기기별 사용자를 더하지 않습니다. 같은 사람이 여러 페이지나 기기를 사용할 수 있기 때문입니다. 지역은 GA4의 IP 기반 추정치입니다.

현재 화면은 기간별 보고서를 사용합니다. 최근 30분 실시간 영역은 2026-10-27에 제거했습니다. 공개 발행 현황은 배포 성공·가동률·사람의 원문 대조를 보증하는 지표가 아닙니다.

### 그래프에서 정확한 수치 읽기

방문자 추이의 열에 마우스를 올리거나 터치하면 **연월일·방문자 수(명)·조회수(회)**를 즉시 표시합니다. 오늘을 선택하면 날짜에 시간도 함께 보입니다. 숫자는 축약하지 않고 천 단위 쉼표를 사용하며, 0명·0회도 그대로 표시합니다. 값이 없는 날짜를 임의로 0으로 추가하지 않고 GA4가 반환한 항목을 보여 줍니다.

키보드는 Tab으로 각 열을 선택하고 Esc로 툴팁을 닫습니다. 낮은 막대도 열 전체에서 반응하며, 좁은 화면의 24시간·28일 그래프는 가로로 이동해 선택합니다. 툴팁은 그래프 폭 안에 표시하고 포인터를 툴팁으로 옮겨도 유지합니다. 기간 변경·새 결과 표시·연결 해제 시 이전 툴팁과 수치를 지웁니다. 호버나 터치로 보고서를 추가 요청하지 않습니다.

기기·섹션·지역·페이지·유입 채널의 가로 막대는 기존 표의 숫자 열과 함께 읽습니다. 기기별·날짜별 방문자를 더해 기간 고유 방문자로 사용하지 않습니다.

## 체류 시간과 읽기 이벤트 해석

| 구분 | 계산 방법 | 읽을 때 주의할 점 |
| --- | --- | --- |
| 전체 체류 | GA4 `userEngagementDuration`을 방문자 수로 나눔 | GA4 참여 시간이며 기사 완독 여부를 뜻하지 않음 |
| 섹션 체류 | `metrics.js`가 보낸 `dwell_<id>`의 초 값을 `eventValue`로 합침 | 화면 가운데에 걸친 섹션 기준의 직접 측정 |
| 섹션을 읽은 사람 | `section_<id>` 이벤트의 사용자 | 메뉴 선택 또는 누적 3초 이상 체류를 읽기 기준으로 사용 |

섹션은 화면 가운데 띠(위아래 45%를 뺀 영역)로 판단합니다. 탭이 숨겨지거나 2분 넘게 스크롤·클릭·키 입력 등이 없으면 시간을 더하지 않습니다. 모은 시간은 탭을 숨기거나 떠날 때 전송합니다. `section_<id>`는 현재 페이지 실행 중 같은 섹션에 한 번만 보내며, 메뉴 선택은 체류 문턱과 별도로 기록합니다. 이벤트 이름에 섹션이 들어 있어 맞춤 측정기준을 따로 등록하지 않습니다.

자동화 브라우저(`navigator.webdriver`)와 `kj-internal` 표시가 있는 브라우저에는 GA4·GoatCounter 스크립트를 넣지 않습니다. 관리자 화면을 열면 내부 표시를 저장하며, 신문 주소의 `?kj-internal=1`로도 설정합니다. `?kj-internal=0`으로 해제합니다.

수치를 비교할 때는 측정 방식이 바뀐 날짜를 함께 봅니다.

| 변경 시점 | 해석 |
| --- | --- |
| 2026-10-27 | 메뉴 선택·3초 문턱·`dwell_<id>` 측정 적용. 이전의 단순 통과 집계와 직접 비교하지 않음 |
| 2026-10-30 | 자동화·내부 방문 제외 적용. 이전 수치에는 이런 접속이 섞일 수 있음 |

## 인증·오류·보안 처리

로그인 전에는 통계를 요청하지 않습니다. Google API가 계정 권한을 검사하며 별도의 사용자 관리·편집 권한·서버 관리자 기능은 없습니다. 관리자 문서에는 방문자 측정 코드를 넣지 않습니다.

| 상황 | 화면 동작 |
| --- | --- |
| 연결 해제·만료·401·403 | 요청 취소, 토큰·통계 제거. 늦은 응답은 세대 번호로 차단 |
| 팝업 종료·동의 거절·인증 도구 차단 | 원인 안내 후 재연결 가능 |
| 요청 지연 | 12초 후 중단 |
| 일반 조회 실패 | 마지막 결과·시각을 유지하고 실패 안내 표시 |
| 기간 변경 | 이전 기간 수치를 비우고 새 기간 조회 |
| 429 한도 초과 | 자동 갱신 중지. 잠시 후 수동 새로고침으로 재시도 |
| 숨긴 탭 | 자동 갱신 중지 |

한 번 갱신할 때 `batchRunReports`를 두 번(5개·4개 보고서) 요청합니다. 하나라도 실패하면 새 결과를 부분 적용하지 않습니다. 0명과 빈 목록은 정상 데이터로 표시합니다.

[보안 정책 생성기](../../dev/pipeline/build/build_security.py)는 관리자 HTML의 실행 코드 해시와 GSI·GA4 API·연결 해제 출처를 포함한 메타 CSP를 만듭니다. 토큰·통계는 저장소·URL·파일에 기록하지 않습니다. GitHub Pages 메타 CSP의 적용 범위와 응답 헤더 제약은 [보안 변경 기록](changes-2026-11-03-layout.md#정적-페이지의-보안)을 참조합니다.

## 검증과 실제 계정 확인

관리자 검사만 실행하려면 저장소 루트에서 시작합니다.

```bash
cd dev/tests/browser
npm ci
npx playwright install chromium
npm run test:admin
```

인증·CSP 등 공통 연결을 바꿨다면 저장소 루트에서 `npm test --prefix dev/tests/browser`로 공개 지면·관리자·보안 검사도 함께 실행합니다.

[admin.cjs](../../dev/tests/browser/admin.cjs)는 OAuth·GA4 응답을 브라우저 요청 경계에서 대체합니다. 24개 시나리오는 로그인 전 요청 차단, 설정 검증, 토큰 비저장, 320~1440px 배치, 빈 결과, 권한/한도/서버 오류, 기간 변경·재시도·늦은 응답 차단, 갱신·시간 초과·만료, 공개 발행 정보와 인증 도구 실패, 신문과 관리자 사이의 테마 공유를 다룹니다. 추이 툴팁은 천 단위 수치·0명·시간별 표시, 포인터 유지·키보드·터치, 320px 다크 화면·28개 열 이동, 기간 변경·빈 응답·연결 해제 시 정리를 추가로 검사합니다. 실제 계정이나 운영 통계를 쓰는 검사가 아닙니다.

운영 계정에서는 허용된 계정과 권한 없는 계정의 차이, GA4 원본 보고서와 수치 비교, 기간 변경, 새로고침 후 재인증, 연결 해제를 별도로 확인합니다. 자동 테스트 통과만으로 운영 OAuth 설정이 완료되었다고 표현하지 않습니다.
