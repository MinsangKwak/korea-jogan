Codex의 기본 예약 기능 자체를 위해 별도 모델 API 키를 준비할 필요는 없습니다. GitHub 조회·쓰기·워크플로 실행 연결이 없거나 만료되면 해당 실행을 실패로 보고하며 인증 정보를 저장소에 넣지 않습니다. 기존 GitHub 예약·재시도와 승인·자동 발행 규칙은 유지합니다.

2026.11.04 공개 호는 이 예약으로 다시 쓰지 않습니다. 첫 대상은 새 자료로 준비하는 2026.11.05 초안이며, 매 실행마다 한국 시간 오늘 날짜와 미공개 상태를 다시 확인합니다. 과거에 빠진 날짜를 소급해 만들지 않습니다.

## 글을 읽을 이유를 첫 문장에 두기

한 항목은 다음 정보 중 필요한 것을 자연스러운 순서로 연결합니다. 모든 항목에 같은 문장 수나 순서를 강요하지 않습니다.

1. **무엇이 달라졌는가:** 결과·결정·현재 확인된 상태를 먼저 씁니다.
2. **무슨 근거인가:** 발표 주체·기준일·핵심 수치를 앞 문장에 연결합니다.
3. **독자에게 어떤 의미인가:** 확인된 적용 대상·시기·조건을 설명합니다. 원문에 없는 비용·영향·원인을 추측하지 않습니다.
4. **무엇이 남았는가:** 계획·후속 일정·미확인 사항이 판단에 필요하면 덧붙입니다.

짧은 기사도 제목을 바꿔 적는 데 그치지 않습니다. 확인된 내용 안에서 대상·조건·시점·배경을 연결해 링크를 열기 전에 맥락을 이해하도록 합니다. 더 설명할 근거가 없으면 짧게 남깁니다. 분량을 채우려고 배경이나 전망을 만들지 않습니다.

주제 요약은 여러 매체가 공통으로 확인한 사실과 기준이 갈리는 부분을 묶어 독립적으로 읽히게 씁니다. 매체별 제목 목록을 문장으로 이어 붙이지 않습니다. 같은 뜻의 문장·수치는 불필요하게 반복하지 않되, 근거 보존 검사 때문에 삭제할 수 없는 항목은 임의로 지우지 않습니다.

문단마다 하나의 판단을 담고, 긴 문장은 주어와 서술어가 가까워지도록 나눕니다. 핵심 설명이 짧은 문단 몇 개로 읽히면 충분합니다. 문장 수·문단 수·검색 키워드 횟수를 품질 점수로 삼지 않습니다.

## 문체 예시: 결과를 먼저 읽고 근거를 따라가기

아래는 2026.11.04호 `lead.standfirst`의 기존 텍스트를 사용한 예시입니다. 공개 호를 자동 수정하거나 원문을 새로 대조한 결과가 아닙니다. 실제 적용 전에는 원문과 사실 관계를 다시 확인합니다. 수치·기준월·발표 주체·추정/전망을 유지하면서 첫 문장을 결과 중심으로 바꿉니다.

**편집 전**

> 국가데이터처가 3일 발표한 10월 소비자물가 상승률은 2.8%로 9월(2.9%)보다 0.1%포인트 낮아졌습니다. 농축수산물은 1.7% 내렸지만 석유류와 가공식품·외식은 올랐습니다. 재정경제부는 석유 최고가격제가 상승률을 0.8%포인트 낮췄다고 추정했고(정부 추정), 한국은행은 11월에도 2%대 후반이 이어질 것으로 전망했습니다(전망).

**편집 후 예시**

> 10월 소비자물가 상승률은 2.8%로 9월(2.9%)보다 0.1%포인트 낮아졌습니다. 국가데이터처가 3일 발표했습니다. 농축수산물은 1.7% 내렸지만 석유류와 가공식품·외식은 올랐습니다.
>
> 재정경제부는 석유 최고가격제가 상승률을 0.8%포인트 낮췄다고 추정했습니다(정부 추정). 한국은행은 11월에도 2%대 후반이 이어질 것으로 전망했습니다(전망).

숫자가 같더라도 비교 대상이나 원인을 바꾸면 같은 사실이 아닙니다. 이 예시에서는 정부의 효과 추정과 한국은행의 전망을 실제 관측 결과와 나눠 읽도록 했습니다. 모든 글을 같은 길이로 늘리거나 나누는 규칙은 아닙니다.

## 사실을 다시 쓸 때는 원문부터 확인

문장의 의미나 사실 관계를 다시 구성하기 전에는 해당 원문·공식 자료를 읽습니다. 원문의 발표일·수정일과 초안의 전날 23:59 자료 기준도 대조합니다. 다시 읽는 동안 나온 새 사실을 몰래 추가하는 작업은 하지 않습니다.

| 자료 상태 | 편집 범위 |
| --- | --- |
| 원문을 다시 읽고 기존 사실을 확인 | 확인된 내용을 바탕으로 문장을 재구성하되 수치·상태·귀속 유지 |
| 본문 접근이 막히거나 링크가 실패 | 우회하지 않음. 의미 보존이 확실한 오탈자·중복 표현 수준만 검토하고 불확실하면 유지 |
| `read: false` 또는 `body_read: false` | 제목·허용된 요약에서 확인한 범위를 넘지 않음. 열람 실패 고지와 필드값 유지 |
| 출처끼리 숫자·범위가 다름 | 차이를 남김. 한쪽을 정답으로 택하거나 평균·새 수치 생성 금지 |
| 혐의·추정·예정·전망·미확정 | 법적·사실적 단계와 누구의 주장인지를 그대로 유지 |

“함께 발생했다”를 “때문에 발생했다”로, “정부는 예상했다”를 “앞으로 그렇게 된다”로 바꾸지 않습니다. 공식 발표·전문가 해석·당사자 주장도 서로 구분합니다. 원문 문장·기사 전문을 복제하거나 JSON에 추가 저장하지 않습니다.

AI가 원문에 접근했더라도 기존 `read`·`body_read`·`review`를 승인이나 사람 확인으로 바꾸지 않습니다. 기존 기록을 바꿔야 한다면 편집 자동화 범위에서 벗어나 별도로 보고합니다.

## 자동 편집이 쓸 수 있는 필드

**오늘 호 JSON에서 아래 경로의 기존 문자열만 수정할 수 있습니다.** `i`·`j`는 이미 있는 배열 원소의 위치이고, 시도명은 이미 있는 `regions.summary` 키입니다. JSON 구조나 스키마를 늘리지 않습니다.

| 허용 경로 | 용도 |
| --- | --- |
| `headline` | 호의 한 줄 요약 |
| `lead.headline` | 편집한 머리기사 제목 |
| `lead.standfirst` | 머리기사의 핵심 설명 |
| `briefs[i].k`, `briefs[i].m` | 보조 소제목과 설명 |
| `themes[i].summary[j]` | 주제별 요약 문단 |
| `national.flow[i]` | 전국 뉴스의 흐름 |
| `national.items[i].summary` | 전국 기사 설명 |
| `regions.summary.<기존 시도명>` | 시도별 전체 요약 |
| `regions.items[i].summary` | 지역 기사 설명 |

`regions.flow`는 현재 스키마에 없습니다. 새 필드를 만들어 대신 쓰지 않습니다. 배열 길이·순서, 객체 키, 기사·주제의 추가·삭제·교체는 허용하지 않습니다. 원문 기사 제목 `articles[].title`·`national.items[].title`·`regions.items[].title`과 편집 제목 `lead.headline`은 구분합니다.

허용 경로 밖의 데이터는 구조·값 모두 같아야 합니다. 특히 다음 내용은 자동 편집에서 바꾸지 않습니다.

- `date`·`collectedAt`·`status`·`review`·`late`와 색인·추적·정정 파일
- 숫자 카드·도표·비교표·일정·기관명·출처·원문 제목·URL·발표일·기준일
- `read`·`body_read`·`figures`·`figure_source`·`limits`와 혐의·단계·확인 범위
- 항목 ID·분류·지역·검색 키워드·링크·차트·상설 지표

**허용된 문자열 안의 사실도 보호 대상입니다.** 수치·부호·단위·금액·비율·날짜·기간·시각·고유명·비교 대상·인용 귀속·제약을 바꾸거나 새로 만들 수 없습니다. 숫자를 다른 허용 필드로 이동해 검사를 피하지 않습니다. 사실 수정이 필요하면 원문과 차이를 보고하고 별도 조사·정정으로 처리합니다.

## 00시 한 번의 실행 순서

1. 한국 시간 오늘 날짜를 정하고 원격 `dev`의 40자리 SHA를 기록합니다. [런북](runbook.md)의 전날 23:59 자료 기준으로 새 자료를 조사합니다. 오늘 호가 이미 공개됐으면 재작성하지 않고 보고합니다.
2. 출처·열람 범위·실제 수집 시각을 남겨 `status: draft`인 오늘 호를 만듭니다. 과거 호의 승인·사람 확인 기록을 새 호에 복사하지 않습니다. 새 기사·수치의 작성은 조사 단계이며, 아직 편집 보존 기준을 만드는 단계입니다.
3. **문체를 바꾸기 전의 사실 초안 JSON을 별도 임시 파일로 보존하고 기본 검사를 통과시킵니다.** 이 파일은 편집 전후 비교에만 쓰며 저장소에 올리지 않습니다. 기사 전문을 추가 저장하지 않습니다.
4. 조사 때 확인한 원문을 다시 대조하며 필요한 문장만 허용 경로 안에서 편집합니다. 초안 기준을 만든 뒤 새 사실·수치·출처를 추가해야 한다면 편집으로 처리하지 않고 조사로 돌아가 기준 파일을 다시 확정합니다. 검사에 맞추려고 기준 파일을 사후 덮어쓰지 않습니다.
5. 아래 편집 보존 검사와 기본 검사를 순서대로 실행합니다. 허용 경로 밖 변경, 구조·배열 순서 변경, 숫자·부호·단위·날짜·URL·확인 기록 변경은 적용하지 않습니다. 주어·귀속·부정·추정·예정·인과 관계는 수정 전후 읽어 대조하고 애매하면 원문 표현을 유지합니다.
6. 발행 색인에는 오늘 날짜와 `latest`를 반영합니다. 추적 사안은 새 근거가 실제로 생긴 항목만 기존 조사·확인 원칙에 따라 갱신합니다. 오늘 초안+색인과 추적 갱신은 역할별 커밋을 나눕니다. 코드·과거 호·승인·정정 파일은 함께 바꾸지 않습니다.
7. 분리 브랜치의 검증된 커밋을 준비하고 원격 `dev`가 시작 SHA와 같은지 다시 확인합니다. 같은 경우에만 예상 SHA를 사용한 비교 후 갱신으로 **직접 `dev`에 반영**합니다. 이 일일 조사에는 별도 PR 승인 단계를 두지 않습니다. 달라졌다면 동시 변경을 덮어쓰거나 강제 push하지 않고 보고합니다.
8. 원격의 오늘 호·색인·커밋을 다시 확인하고 날짜·머리기사·주제·기사 수·대체한 매체·검사 결과·반영 여부를 짧게 보고합니다. 실패·건너뜀·동시 변경을 완료나 배포 성공으로 보고하지 않습니다. `main`·`deploy` 직접 갱신과 승인 명령 실행은 하지 않습니다.

새 호는 기준 커밋에 아직 파일이 없을 수 있으므로 `--baseline-file`로 조사 직후 사실 초안을 대조합니다. 실제 임시 파일 경로와 한국 시간 오늘 날짜로 바꿔 실행합니다.

```bash
python3 dev/pipeline/publish/validate.py
python3 dev/pipeline/publish/check_editorial.py --baseline-file /tmp/jogan-facts-YYYY-MM-DD.json --date YYYY-MM-DD
python3 dev/pipeline/publish/validate.py
```

첫 `validate.py`는 사실 초안을 만든 직후, 나머지 두 검사는 문체 편집 후에 실행합니다. 이미 원격에 있는 오늘 미공개 초안만 편집하는 경우에는 기준 SHA에 그 파일이 있을 때 아래 방식도 사용할 수 있습니다.

```bash
python3 dev/pipeline/publish/check_editorial.py --base-ref <기준-dev-40자리-SHA> --date YYYY-MM-DD
```

[편집 검사](../../dev/pipeline/publish/check_editorial.py)는 같은 호의 수정 전후를 대조해 허용 필드·자료 구조·숫자와 단위의 필드별 보존·본문 URL·한정 표현 등을 검사합니다. 숫자의 쉼표·단위 앞 공백·유니코드 마이너스는 정규화해 비교합니다. 공개 호는 대상에서 제외합니다. 토큰 일치만으로 고유명사·주체와 대상·인용 귀속·인과 관계의 보존을 증명하지 못하므로 원문과 의미 대조가 필요합니다. 검사 통과를 편집 품질·원문의 진실성·완독·사람 확인의 증거로 표현하지 않습니다.

커밋 예시는 초안+색인에 `data(issue): YYYY-MM-DD호 조사와 문장 편집 초안`, 추적 갱신에 `data(site): 확인된 이슈 추적 근거 갱신`입니다. 편집된 초안의 공개는 기존 사람 확인 또는 아침 자동 발행 절차가 담당합니다.

## 06:05 공개 확인의 현재 실행 범위

인수인계 문서의 원래 역할은 `publish.yml`을 `ref=main`으로 직접 실행한 뒤 공개를 확인하는 것입니다. **현재 GitHub 연결 도구에는 `workflow_dispatch` 실행 기능이 없고 GitHub CLI 인증도 없어, Codex 예약은 공개 확인·읽기 전용 진단만 수행합니다.** 기존 성공 작업 재실행으로 대체하려던 확인은 자동 승인 검토에서 거절됐습니다. 직접 실행은 별도 명시적 승인과 사용할 실행 경로 확인 전까지 활성화하지 않습니다. 빈 커밋·push 등으로 우회하지 않습니다.

실제 발행은 기존 GitHub 06:07·06:37·07:17·08:17 예약이 담당합니다. 06:05 확인 작업은 3~5분 뒤 공개 색인 `https://korea-jogan.com/data/issues/index.json`의 `latest`가 한국 시간 오늘인지 15초 간격으로 최대 6분 확인합니다. 대기는 한 번에 60초 이하로 나눕니다. 워크플로 기록과 실제 공개 날짜 일치는 별도로 확인합니다.

공개됐으면 한 줄 결과만 남기고 별도 성공 알림은 보내지 않습니다. 공개되지 않았으면 초안 존재 → 색인 `latest` → 검사 결과 → 브랜치 빨리 감기 순으로 읽기 전용 진단을 하고 실패 이유를 알립니다. **이 확인 작업은 코드·데이터를 고치거나 강제 push하지 않습니다.** 기존 재시도 예약을 끄거나 바꾸지도 않습니다.

## 공개된 글과 성과의 경계

현재 공개된 호를 일괄 다시 쓰지 않습니다. 사용자가 특정 공개 호의 편집을 요청하면 별도 작업으로 원문·수정 범위를 확인하고, 의미·사실을 고친 경우 [정정 절차](runbook.md#정정)를 적용합니다.

글을 개선한 뒤에는 원문 이동·섹션 읽기·재방문 등 실제 반응을 확인합니다. 검색 키워드 반복, 과장 제목, 자동 생성 분량을 늘리는 방식으로 노출을 약속하지 않습니다. 읽기 품질 개선·검색 수집 조건·실제 독자 증가는 서로 다른 확인 항목입니다.
