# 발행 데이터 규격

**하루 한 호를 날짜별 JSON으로 저장하고, 화면과 발행 파이프라인이 같은 데이터를 사용합니다.** 값뿐 아니라 출처·기준일·확인 상태를 남겨 발행 이후에도 판단 근거를 추적할 수 있게 했습니다.

검사 구현은 [validate.py](../../dev/pipeline/publish/validate.py), 화면 해석은 [컴포넌트 코드](../../dev/web/src/components/)가 기준입니다. 아래에서 ‘검사’로 표시한 내용은 현재 스크립트가 확인하며, ‘작성 기준’은 조사·편집 과정에서 지켜야 합니다.

## 파일과 색인

| 경로 | 내용 |
| --- | --- |
| `dev/web/data/issues/YYYY-MM-DD.json` | 날짜별 호 |
| `dev/web/data/issues/index.json` | 최신 호와 호 목록 |
| `dev/web/data/corrections.json` | 전체 호의 정정 이력 |
| `dev/web/data/live.json` | 배포 시 생성하는 최신 공식 숫자. Git에는 저장하지 않음 |

```json
{ "latest": "2026-10-22", "issues": ["2026-10-22", "2026-10-21"] }
```

`latest`는 화면이 기본으로 여는 호입니다. 검사기는 이 값이 `issues` 안에 있는지, 나열된 파일이 모두 존재하는지 확인하고 모든 호를 검사합니다. 목록은 최신순으로 작성하지만 정렬 자체를 검사하지는 않습니다.

## 호의 최상위 항목

필수 키는 `date`, `lead`, `briefs`, `nums`, `themes`, `items`, `industries`, `trade`, `debt`, `fiscal`, `nps`, `agenda`, `limits`의 13개입니다. `status`도 허용 상태인지 별도로 검사합니다. 모든 하위 필드가 자동 검사되는 것은 아닙니다.

| 키 | 형식 | 역할·작성 기준 |
| --- | --- | --- |
| `date` | 날짜 문자열 | 발행일. 파일명과 일치하는지 검사 |
| `collectedAt` | ISO 8601 문자열 | 수집 시각. 공개 호는 시간대 포함과 06시 마감을 검사 |
| `late` | 객체 | 06시를 넘겨 모은 호만 작성. 늦은 이유 `reason`과 자료 기준 시각 `cutoff`(전날 23:59 이전) |
| `status` | 문자열 | `prototype`, `draft`, `published` 중 하나 |
| `review` | 객체 | 공개 전환 주체·시각·확인 범위·자동 여부 |
| `headline`, `topic`, `notes` | 문자열 | 한 줄 제목·주제·비고 |
| `lead` | 객체 | 머리기사·요약·핵심 수치 |
| `briefs` | 배열 | 오늘 꼭 볼 숫자. `{k, m, href}` 4~6개를 작성 기준으로 사용 |
| `nums` | 배열 | 출처가 연결된 경제 숫자 |
| `national`, `regions` | 객체 | 분야별 전국·시도별 기사와 흐름 요약 |
| `agenda`, `agendaSrc` | 배열·문자열 | `{day, dow, cat, t}` 일정 목록과 출처 |
| `items` | 배열 | `{k, v, y, c}` 수출입 품목·금액·전년 대비·표시 분류 |
| `industries` | 배열 | `{name, sum, f, news}` 산업별 요약. `f`는 `[항목, 값, 출처]` 목록 |
| `trade` | 객체 | `{intro, stats, src, oct}` 수출입 개요 |
| `debt` | 배열 | 연도별 국가채무·GDP 비율·결산 또는 전망 |
| `fiscal` | 객체 | `monthly`, `summary`, `outlook`의 `{k, m, v}` 목록과 출처 |
| `nps` | 객체 | `kv`, `alloc`, `reform`과 출처. 자산 배분은 `{a, amt, s}` |
| `themes` | 배열 | 주제별 요약·수치 비교·기사·검색 키워드 |
| `limits` | 문자열 배열 | 본문 미확인, 출처 대체, 날짜 범위 조정 등 수집 한계 |

## status · review

조사 작업은 `draft`를 작성합니다. `published`는 공개 가능한 상태이며, 사람 확인과 자동 발행을 모두 포함합니다. 두 경로는 `review.auto`로 구분합니다.

```json
{
  "status": "published",
  "review": {
    "by": "확인자 이름",
    "at": "2026-10-22T05:40+09:00",
    "scope": ["lead", "nums", "themes.diffs"]
  }
}
```

```json
{
  "status": "published",
  "review": {
    "by": "자동 발행",
    "at": "2026-10-22T06:03+09:00",
    "scope": [],
    "auto": true
  }
}
```

| 항목 | 현재 검사·운영 기준 |
| --- | --- |
| 공개 전환 | `approve.py`는 초안만 전환. `--by`와 `--auto`는 함께 사용할 수 없음 |
| 확인 기록 검사 | 공개 호의 비어 있지 않은 `by`, ISO 형식의 `at` 검사. 실제 대조 수행 여부는 자동 확인하지 못함 |
| 수집 마감 검사 | 공개 호의 `collectedAt`은 시간대가 있어야 하며 발행일 한국 시간 06시 이하여야 함. 넘겼다면 `late.reason`이 있고 `late.cutoff`가 발행일 0시 전이며 수집이 발행일 안이어야 함 |
| 배포 검사 | `validate.py --deploy`는 색인에 초안이 하나라도 있으면 실패 |
| 시안 | `prototype`은 화면에서 시안으로 표시. 공개 호 확인 규칙과 초안 차단 대상에서 제외 |

작성 기준은 전날 23:59까지 발표·보도된 자료입니다. 시장 숫자는 전 거래일 종가를 사용합니다. 수집 시각의 06시 제한만으로 개별 기사의 보도 시각까지 검사되는 것은 아닙니다.

## lead

```json
{
  "kicker": "분류",
  "headline": "머리기사 제목",
  "standfirst": "결론부터 작성한 요약",
  "facts": [{ "t": "항목", "v": "값", "m": "기준과 출처" }],
  "meta": "발표 및 수집 정보"
}
```

`facts`는 핵심 수치 3개를 작성 기준으로 합니다. 요약과 수치는 원문 대조 대상이며, `lead` 키의 존재 검사만으로 내용이 검증되지는 않습니다.

## nums

```json
{
  "k": "지표 이름",
  "v": "표시할 값",
  "dir": "up",
  "d": "변동폭",
  "ref": "비교 기준",
  "grade": "A",
  "src": {
    "name": "출처 기관",
    "title": "자료 제목",
    "pub": "발표일",
    "base": "통계 기준일",
    "url": "https://example.org/source"
  }
}
```

출처 기관명과 `https://` 링크, `up`·`down`·`flat` 방향 값은 검사 대상입니다. 링크가 실제로 열리는지와 값이 원문에 일치하는지는 별도로 확인해야 합니다.

`grade`는 A 공식 확정 통계, B 공식 잠정 통계, C 공식 정책 발표, D 언론 보도·민간 집계, E 분석·계산으로 자료의 성격을 구분합니다. 발표일과 기준일을 나누고, 공식 발표를 기사에서 인용했다면 자료 제목에 그 관계를 밝힙니다.

## national · regions

```json
{
  "flow": ["오늘의 흐름 1", "오늘의 흐름 2", "오늘의 흐름 3"],
  "items": [{
    "cat": "사회",
    "title": "기사 제목",
    "outlet": "언론사",
    "url": "https://example.org/article",
    "date": "YYYY-MM-DD",
    "body_read": false,
    "summary": "확인한 범위에서 별도로 작성한 요약",
    "figures": ["원문에서 확인한 숫자"]
  }]
}
```

| 항목 | 작성·검사 기준 |
| --- | --- |
| 전국 분류 | `사회`, `사건·안전`, `날씨·재난`, `안보·외교`, `국제`, `과학·IT`, `생활·물가`, `문화·스포츠` |
| 지역 기사 | `region` 추가. 서울·부산·대구·인천·광주·대전·울산·세종·경기·강원·충북·충남·전북·전남·경북·경남·제주만 검사에서 허용 |
| 지역 요약 | `regions.summary`에 시도 이름을 키로 한 한 줄 요약 |
| 공통 검사 | 기사마다 `https://` 링크와 비어 있지 않은 요약 |
| 열람 기록 | 본문을 읽지 못했다면 `body_read: false`. 요약도 실제 확인 범위에 한정 |

분류 문자열은 [config.js](../../dev/web/src/core/config.js)에 있습니다. 기사 수·17개 시도 전체 포함 여부·본문 열람의 진위는 현재 검사기가 보장하지 않습니다.

## themes

주제 하나에 요약·숫자 비교·기사 목록을 모읍니다. 독자가 요약에서 근거로 이동할 수 있게 연결한 구조입니다.

```json
{
  "id": "topic-id",
  "title": "주제 이름",
  "keywords": ["검색 키워드"],
  "period": "수집 기간",
  "summary": ["직접 작성한 AI 요약"],
  "diffs": [{
    "q": "숫자가 다른 이유는 무엇인가",
    "a": "비교 시점 또는 집계 범위의 차이",
    "cols": ["기준", "값"],
    "rows": [["기준 A", "값 A"], ["기준 B", "값 B"]],
    "pick": [0, 1]
  }],
  "articles": [{
    "outlet": "언론사",
    "region": "국내",
    "title": "기사 제목",
    "url": "https://example.org/article",
    "date": "YYYY-MM-DD",
    "read": false
  }]
}
```

검사기는 `summary`, `articles`, `keywords`가 비어 있지 않은지와 기사 링크 형식을 확인합니다. 기사 본문은 저장하지 않습니다. `region`은 국내·해외로 작성하고, 본문을 읽지 못하면 `read`를 `false`로 둡니다.

주제의 첫 번째 `diffs`가 홈 비교 카드에 사용됩니다. `pick`은 홈에 표시할 두 행 번호이며, 생략하면 첫 행과 마지막 행의 첫 열을 사용합니다. `keywords`와 제목은 그날 호의 검색 점수에 사용됩니다.

## debt

한 행은 `[연도, 금액(조 원), GDP 대비 비율(%), 구분]`입니다.

```json
[[2015, 591.5, 34, "결산"], [2030, 1734.1, 49, "중기전망"]]
```

위 숫자는 형식 설명용 예시입니다. 실제 발행에는 해당 기준의 공식 출처를 대조합니다.

연도 오름차순, 금액 100~5,000조 원, 비율 10~150%를 검사합니다. 이 범위는 입력 실수를 찾기 위한 제한이며, 실제 수치의 정확성을 보장하지 않습니다. 화면은 구분이 결산이 아니면 전망 형태로 표시합니다. 확인되지 않은 연도는 행을 넣지 않아 미확인으로 표시합니다.

## corrections.json

```json
{
  "items": [{
    "date": "2026-10-22",
    "issue": "2026-10-21",
    "section": "경제 · 지표 이름",
    "before": "수정 전 값",
    "after": "수정 후 값",
    "reason": "기준일 오기"
  }]
}
```

예시는 정정 형식을 설명합니다. 모든 키가 필수이며, `date`의 날짜 형식과 `issue`가 실제 색인에 있는지 검사합니다. 호 JSON과 정정 항목은 같은 커밋에 넣습니다. 제목은 `fix(issue): YYYY-MM-DD호 항목 정정` 형식을 사용합니다.

## live.json

배포 때 생성하며 승인된 조간을 덮어쓰지 않습니다. 지난 호를 볼 때나 파일이 없을 때는 최신 숫자 띠를 숨깁니다.

```json
{
  "updatedAt": "2026-10-22T16:17+09:00",
  "source": "한국은행 경제통계시스템(ECOS)",
  "items": [{
    "id": "kospi",
    "k": "코스피 종가",
    "v": "표시할 값",
    "dir": "up",
    "d": "변동폭",
    "src": { "base": "기준일" }
  }],
  "missing": []
}
```

`items`는 핵심 숫자와 같은 표시 구조이며 코스피·코스닥 종가, 원·달러 매매기준율, 기준금리 순입니다. 누락 항목과 사유는 `missing`에 기록합니다. 생성 후 12시간이 지나면 화면에 갱신 지연을 알립니다. 장중 시세가 아니며 자동 갱신·사람 확인 전임을 표시합니다.

## 작성과 검증 순서

지난 호를 틀로 삼되 발행일·수집 시각·당일 기사·숫자·일정은 다시 확인합니다. 상설 지표는 새 공식 발표가 있을 때만 바꾸고 기존 기준일을 유지합니다. 초안 상태로 색인을 갱신하고 검사한 뒤, 사람 확인 또는 자동 발행 경로로 공개합니다. 실행 명령과 실패 대응은 [발행 런북](runbook.md)에 있습니다.
