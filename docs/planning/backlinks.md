# 외부 링크와 검색 유입 확인 계획

**서비스를 소개하는 외부 페이지를 정리하고, 실제 검색 유입 변화를 확인하는 계획입니다.** 홍보 글 게시·Notion 공개·Search Console 재조회는 이 문서 편집으로 수행하지 않았습니다. 완료 여부와 효과는 실행 증거를 확인한 뒤 기록합니다.

[문서 안내](../README.md) · [서비스 기획과 측정 기준](01-product.md) · [호별 페이지 생성](../../dev/pipeline/build/build_pages.py)

## 먼저 할 일

| 순서 | 확인·작업 | 완료 판단에 필요한 기록 |
| --- | --- | --- |
| 1 | 포트폴리오·프로필에서 서비스 소개와 주소 확인 | 실제 공개 페이지 주소와 접근 상태 |
| 2 | 만든 과정이나 데이터 비교 사례를 기술 글로 정리 | 게시한 글 주소·게시일·관련 호 주소 |
| 3 | Search Console에서 해당 URL과 링크 보고서 확인 | 조회일·보고서 범위·색인/링크 상태 |
| 4 | 검색 노출·클릭과 사이트 행동을 함께 비교 | 같은 기간의 검색 보고서와 GA4 집계 |

사이트 소개에는 `https://korea-jogan.com/`, 특정 호의 사례에는 `/YYYY-MM-DD` 주소를 사용합니다. 최신 호가 바뀌어도 사례의 날짜와 내용이 구분되도록 하기 위한 기준입니다.

## 현재 구현돼 있는 도착 페이지

저장소에서 확인할 수 있는 기능입니다. 외부 링크의 수나 검색 순위 효과를 확인했다는 뜻은 아닙니다.

- 최신 호·호별 HTML, 제목·설명·canonical·JSON-LD를 생성합니다.
- RSS·사이트맵을 공개 호 목록에서 만들고, 옛 `?d=` 주소는 있는 호의 주소로 옮깁니다.
- 픽셀 삽화와 연결한 OG 이미지·파비콘을 제공합니다.
- `robots.txt`에서 크롤러별 접근 범위를 안내합니다. 이는 권고이며 접근 통제를 대신하지 않습니다.
- [GA4 운영 화면](../dev/ga4-admin.md)은 공개 발행 상태를 표시하고, OAuth 설정과 조회 권한을 갖춘 계정의 통계를 조회하도록 구현돼 있습니다.

## 외부 소개에 담을 내용

주소만 반복해서 남기기보다 이 서비스에서 실제 구현한 사례를 설명합니다.

| 소개 위치 | 적을 내용 | 연결할 곳 |
| --- | --- | --- |
| GitHub README·저장소 소개 | 데이터 신문의 목적과 출처 확인 흐름 | 서비스 첫 화면·기술 문서 |
| 공개 포트폴리오·개발자 프로필 | 직접 맡은 기획·UI·검사·발행 역할 | 서비스·대표 구현 근거 |
| 기술 글 | 사람 확인/자동 발행 분리, PC·모바일 정보 배치, 정정 처리 사례 | 관련 코드·고정된 호별 주소 |

Notion 포트폴리오를 사용할 경우 공유·게시 설정과 검색 엔진 관련 옵션을 실제 화면에서 확인합니다. 현재 공개 상태를 이 문서만으로 단정하지 않습니다. 공개·링크 추가만으로 색인이나 보고서 반영이 보장되지는 않습니다.

## 측정과 판단

사이트 수와 링크된 페이지 수를 따로 기록합니다. 보고서의 집계 단위가 다를 수 있으므로 조회 화면의 항목명·기간도 함께 남깁니다.

노출·클릭이 적다는 사실만으로 원인을 외부 링크 부족 하나로 확정하지 않습니다. 색인 상태·검색어·국가·기기·페이지별 노출을 보고, 서비스 안에서는 출처·비교·섹션 읽기 행동을 함께 확인합니다. 공개 직후의 변화에 고정된 반영 기한이나 상승 목표를 약속하지 않습니다.

후속 기록에는 조회일, 작업한 페이지 주소, 바뀐 설정, 비교 기간과 결과를 적습니다. 변화가 없다면 페이지 접근·색인·보고서 반영 상태부터 다시 확인합니다.

## 하지 않는 작업

링크 구매·교환 모임·자동 등록 서비스, 주제와 무관한 게시판·댓글에 주소만 남기기, 같은 글의 반복 게시를 운영 방식으로 사용하지 않습니다. 실제 구현과 사례를 설명하는 소개만 준비하며, 외부 게시·연락은 별도 실행 요청과 확인을 거칩니다.
