# 서비스 기획과 검증 계획

**대한민국 조간은 숫자의 출처와 비교 기준을 확인하며 읽는 데이터 신문입니다.** 전국·지역 소식과 경제·산업·재정 지표를 하루 한 호로 정리하고, 같은 수치가 달라 보이는 이유를 원문과 연결합니다.

이 문서는 2026.11.05 현재 제공하는 기능과 앞으로 검증할 가설을 나눠 설명합니다. 40~50대 독자의 읽기를 고려해 상단 삽화를 없애고 본문 18~19px·큰 글자 23px, 라이트 기본·선택형 다크 화면과 같은 모양의 스위치를 적용했습니다. [문서 안내](../README.md) · [최신 운영 확인](../dev/changes-2026-11-05.md) · [디자인 기준](../../design/guide.md)

## 현재 제공하는 읽기 흐름

전국 뉴스를 1면, 이슈 추적을 2면으로 두었습니다. 이후에는 주요 뉴스와 수치 비교를 읽고 관심 지역·분야·근거로 이동합니다.

| 순서 | 섹션 | 독자가 확인하는 정보 |
| --- | --- | --- |
| 1 | 전국 | 분야별 기사와 오늘의 흐름 |
| 2 | 이슈 추적 | 현재 단계·다음 확인 사항·타임라인·근거 기사 |
| 3 | 홈(주요 뉴스) | 머리기사·핵심 수치·기준이 다른 숫자 |
| 4 | 지역 | 6개 권역으로 묶은 17개 시도 소식 |
| 5 | 언론 | 같은 주제의 요약·수치 비교·매체별 기사와 검색 |
| 6 | 정치 | 임기·선거·예산 일정과 이번 주 일정 |
| 7 | 경제 | 지수·환율·유가·금리의 값·변동·기준일·출처 |
| 8 | 산업 | 수출입과 반도체 외 주력산업·품목별 비교 |
| 9 | 재정 | 국가채무·월간 재정·국민연금의 장기 흐름 |

상단 추적 막대는 필요할 때 패널을 열거나 현재 세션에서 숨길 수 있습니다. 숨긴 뒤에도 재진입 버튼을 남기고, 패널을 닫으면 읽던 위치와 포커스로 돌아갑니다. 지난 호에는 현재의 추적 상태를 붙이지 않습니다.

### PC와 모바일의 우선순위

**핵심 정보는 항상 보이고, 보조 내용의 기본 펼침 상태는 화면 폭에 따라 구분합니다.** 닫힌 영역을 반드시 다시 열어야 현재 상황을 이해하는 구조는 피했습니다.

| 영역 | PC에서 비교하는 방법 | 모바일에서 먼저 보이는 정보 |
| --- | --- | --- |
| 전국 | 기사 한 편과 제목 목록을 나란히 두고 선택한 기사·출처를 갱신 | 본문 다음에 제목 목록 |
| 이슈 추적 | 1,100px부터 사안 카드 두 개를 나란히 배치하고 긴 본문은 내부 스크롤 | 요약·현재 단계·다음 확인·주의사항. 진행 일정과 상세 근거는 펼침 영역 |
| 머리기사 | 두 열 중 짧은 쪽 높이에 맞추고 긴 쪽만 스크롤 | 머리기사·핵심 수치. 보조 주제와 숫자 목록은 기본 접기 |
| 언론 | 제목·설명 옆에 검색창 배치 | 설명 아래 검색창을 계속 표시 |
| 일정·재정 | 임기·D-Day와 주간 일정, 국가채무 그래프와 예산·연금의 폭을 나눔 | 각 내용을 자연 높이의 한 열로 읽음 |
| 경제 | 값·변동·기준일을 같은 순서로 비교하며 순환 이동. 설명·출처는 목록 아래 한 건씩 펼침 | 한 카드 중심의 핵심 수치, 선택하면 아래 공용 상세 |
| 산업 | 대표 수치로 다섯 주력산업을 비교하고 선택한 분야의 전체 지표·기사는 아래에 표시 | 한 열의 대표 수치와 선택한 분야 상세. 품목별 그래프는 기본 접기 |

보조 내용은 901px 이상에서 기본으로 펼치고, 900px 이하에서는 기본으로 접습니다. 긴 근거 기사 표는 3건을 넘으면 PC에서도 접어 두고 건수를 표시합니다. 화면 폭별 사용자 선택을 기억하며, 메뉴로 접힌 내용에 바로 이동하면 먼저 펼칩니다.

경제 순환 슬라이드는 이전·다음·방향키·스와이프와 재생 제어를 제공합니다. 호버·포커스·숨긴 탭·화면 밖에서는 멈추고, 터치하거나 출처를 열면 사용자가 다시 켜기 전까지 자동 넘김을 중지합니다. 라이브러리를 불러오지 못하면 전체 지표 목록을 유지합니다.

로고는 조간의 첫 자음 `ㅈ`과 새벽빛 획을 사용하며, 공유 이미지에는 신문 너머로 해가 뜨는 ‘첫 빛’을 적용했습니다. 공유용 이미지와 본문 장식은 역할을 나눠 지면을 열 때 상단 삽화를 요청하지 않습니다.

## 해결하려는 문제

같은 사건의 숫자가 달라도 어느 한쪽이 반드시 틀린 것은 아닙니다. 비교 시점·집계 기간·포함 범위가 다를 수 있으므로 값과 조건을 함께 보여 줍니다.

| 관찰한 상황 | 반영한 요구사항 |
| --- | --- |
| 지표의 증감률이 기사마다 다름 | 비교 기준과 기간을 나란히 표시 |
| 발표일과 통계 기준일이 다름 | 두 날짜를 별도 필드로 저장 |
| 확정값과 전망값이 함께 인용됨 | 배지·그래프 형태로 상태 구분 |
| 지역·전통 산업 소식이 묻힘 | 지역과 주력산업을 독립 섹션으로 구성 |
| 한 호의 내용이 길어짐 | PC 비교 배치와 모바일의 핵심 정보 우선 노출 |

기존 호의 비교 사례는 기능 설명용입니다. 개별 보도의 오류를 확정하려면 원문과 기준을 먼저 대조해야 합니다.

## 확인 수준과 운영 책임

| 정보 | 화면과 데이터의 표현 |
| --- | --- |
| 자료의 성격 | A 확정 통계·B 잠정 통계·C 정책 발표·D 언론/민간 집계·E 분석/계산. 등급이 사실성을 보증하지는 않음 |
| 값의 상태 | 결산·전망 배지와 막대 형태 |
| 사람 확인 여부 | 편집자 확인과 자동 발행을 구분 |
| 자료의 시점 | 발행일·수집 시각·통계 기준일·발표일 |
| 확인 한계 | 본문 열람 여부·대체 출처·누락 정보를 공개 |
| 정정 | 변경 전후 값·사유·정정일을 기록 |

00시 Codex가 안정 `main` 기반 `daily/YYYY-MM-DD`에 조사·초안을 저장하고, 아침 GitHub Actions가 고정 일일 SHA의 CI를 확인해 허용 데이터만 안정 코드에 반영합니다. 개발 `dev`의 미검증 코드는 함께 공개하지 않습니다. 사람이 원문을 대조한 기록과 자동 공개 기록은 `review.auto`로 구분합니다. 자동 검사는 형식·범위·운영 조건을 확인하며 원문의 사실 확인 전체를 대신하지 않습니다.

선관위 특검·무안공항 참사는 보도에 따른 편집상 단계로 관리합니다. 기간 경과는 해결률이 아니며, 조사 종료일이 미확정이면 완료율을 만들지 않습니다. [발행 절차](runbook.md) · [데이터 규격](data-spec.md)

## 먼저 검증할 독자와 행동

경제 기사의 숫자를 업무 보고나 개인 판단에 다시 사용하는 30~50대 직장인을 우선 독자 가설로 잡았습니다. 실제로 숫자의 차이를 확인하는 일이 반복되는지, 출처 확인 기능을 사용하는지 검증할 대상입니다. 특정 연령대의 만족도를 확인했다는 뜻은 아닙니다.

| 가설 | 확인할 행동 | 재검토할 신호 |
| --- | --- | --- |
| 독자는 숫자의 차이를 확인하고 싶어 함 | 홈 비교 카드와 상세 비교 펼침 | 기사만 읽고 비교 기능은 거의 사용하지 않음 |
| 가까운 출처가 확인 행동을 돕음 | 출처 펼침 | 비교는 읽지만 출처를 열지 않음 |
| 주제 탐색이 재사용에 도움을 줌 | 검색 주제와 결과 없음 | 결과 없음이 반복되거나 특정 주제에 편중 |

### 측정할 수 있는 것과 해석의 한계

GA4 측정 ID가 설정돼 있고 [운영 화면](../dev/ga4-admin.md)이 구현돼 있습니다. GoatCounter 주소는 비어 있습니다. 실제 집계 결과를 확인하기 전에는 사용자 증가·재방문·가독성 향상 같은 성과를 제시하지 않습니다.

| 지표 | 확인 방법 | 해석할 때 주의할 점 |
| --- | --- | --- |
| 방문 100회당 확인 행동 | `(split-home + split-open + src-open) / 방문 × 100` | 반복 행동을 포함하므로 방문자 비율이 아니며 100을 넘을 수 있음 |
| 출처 확인 | `src-open`과 기관명 | 펼침 행동이며 외부 원문 방문을 뜻하지 않음 |
| 비교 사용 | `split-home`, `split-open` | 이벤트 합계만으로 사용 방문 비율을 계산할 수 없음 |
| 검색 수요 | `search`의 주제 이름·결과 없음 | 검색어 원문은 전송하지 않음 |
| 섹션 읽기·시간 | `section_<id>`, `dwell_<id>` | 메뉴 진입 또는 머무름 조건을 적용한 운영상 정의이며 정독을 보증하지 않음 |
| 정정 대응 | 신고 이슈·정정 날짜 | 처리 시간은 이슈 시각과 대조해야 함 |
| 발행 지속성 | 호 목록·워크플로·배포 결과 | 호 파일이 있다는 사실만으로 정시 배포를 판단하지 않음 |

GA4의 이벤트 이름에서는 하이픈을 밑줄로 바꿉니다. 자동화 브라우저와 내부 표시 브라우저는 측정에서 제외합니다. 구현 기준은 [metrics.js](../../dev/web/src/core/metrics.js)입니다.

## 범위와 후속 과제

회원·댓글·광고는 초기 범위에서 제외했습니다. 정당 공방과 인물 평가는 다루지 않고 발표·통계·사실·일정에 집중합니다. 기사 본문은 저장하지 않으며 제목·메타데이터·링크와 별도로 작성한 요약을 사용합니다.

다음 과제는 구현 완료 항목이 아닌 검증·확장 계획입니다.

1. 실제 행동 데이터를 검토하고 우선 독자 가설을 2주 단위로 확인합니다.
2. 비교·출처 확인이 적다면 배치·문구·주제 선정부터 재검토합니다.
3. KOSIS·관세청·국회 수집을 확장해 수동 조사 범위를 줄입니다.
4. 호가 누적되면 월·연 단위 아카이브를 검토합니다.
